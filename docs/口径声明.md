## 五、明确"未测 / 未实现"清单（对外引用本项目时必须原样带出）

1. 云 API 轨的延迟、成功率、真实 token 用量与账单、结构化输出稳定性。
2. 界面在真实浏览器里的**人工点击与可用性观察**（本轮由应用内浏览器 + 页面内脚本驱动，测的是服务端行为，不是人机工程）；跨浏览器/移动端渲染**未测**；公网暴露下的 TTFB **未测**（只测了本机 loopback）。
3. 三市分档**已实现**（条文号按员工所在城市解析），但三档差异只在**本机这一批合成事实**上对过账：
   同一批事实分别按三市整档重跑的结论条数对照表**未做**——现有数据里每人只属于一个城市，
   做这张表要复制员工到三档下重跑，本期没有排。
4. **1,000 个真实员工**规模下的整轮校验耗时与举证包导出（v4 的 1,000 行档只测了"复制行后的导出代码形状"，
   396.0 ms 中位、含自含输入）。**v5 补充**：1,000 员工单月**结论密集**合成数据已实测（第 0 节，1,700 条结论、
   导出 P95 1,451.2 ms 达成 ≤3 s）；3,000 员工月的导入/校验与 **12 MiB 实验下的自含导出 + replay + verify**
   已完成（空台账 5,100 条 / 包 731,659 字节；450 行非空台账 4,650 条 / 包 729,492 字节），
   但 **12 MiB 是实验值、不是最终 SLA**；两档都是合成数据，不是真实员工。
5. v4 判据下的整轮耗时与 SQL 语句数**已不再属于未测**：2,904 人日 / 3,215 条 SQL / 347.4 ms 中位
   （见 `reports/性能探针.json`），列在这里只是为了说明旧条目已被替换。
6. 第二人按演示脚本盲跑 30 分钟的实际用时。
7. 向量检索收益（未引入向量库；`vector` 后端只有"如实降级"的测试）。
8. 跨零点班次归属与出差计时长的法规依据——**公开资料里没有**，本项目参数为自设（详见字段口径文档第三节 Q-A/Q-B）。
9. 重放**只承诺同版本代码**：包内规则包版本与当前代码不一致时 `cli replay` 直接拒绝并指向 REV 对账。
   跨版本重放本期不做——那等于宣称能预测判据变更的影响，本项目不做这种宣称。
10. 重放时 `scope` **未记录**的判据参数（夜间窗口、每日/每月加班上限、周最少休息日等）沿用代码默认值，
    不读本机 `.env`（见 `reports/判据修订.md` REV-07 的"已知边界"）。要 100% 钉死全部口径，
    得把这些参数也写进包内 scope，而那会改变输入指纹 → 需你裁定是否升版本（`docs/待确认清单.md` R-8 同源问题）。
