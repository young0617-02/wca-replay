# 数据留存与删除策略（草案）

> **草案性质**：本文件是提交律师审阅的草案，不是法律意见，不可直接作为对客户的承诺或制度发布。
> **需要律师确认的条款**：第 2 条各类数据留存期限的合法性、第 4 条删除方式与审计链不可改写的冲突、第 5 条举证包删除与重放要求的冲突、第 7 条备份残留副本的处理、第 9 条法律保留与争议保全的例外。
> **必须由业务方填空的字段**：客户与供方主体、各类数据留存期限、删除触发与审批人、备份轮换周期、法律保留例外、争议保全期限、删除证明形式。

## 1. 目的与适用范围

1.1 本策略适用于系统在 PoC 与后续部署中接触的全部客户数据，包括原始输入、数据库记录、举证包、审计链、临时库、导出暂存、问答记录与日志。
1.2 本策略不改变任何既有技术行为；技术现状以 `docs/数据最小化方案.md` 与 `docs/安全与证据链现状.md` 为准。

1.3 本策略适用于客户 `[[客户全称]]` 与供方 `[[供方全称]]` 之间。

## 3. 删除触发

| 触发情形 | 说明 | 需谁批准 |
| --- | --- | --- |
| 留存期限届满 | 按第 2 条到期 | `[[删除审批人]]` |
| 处理目的已实现且无其他必要 | 客户书面确认 | `[[删除审批人]]` |
| 客户终止或撤回委托 | 按合同与 DPA 执行 | `[[删除审批人]]` |
| 数据主体提出删除请求 | 需先评估与举证包、审计链的冲突 | `[[删除审批人]]` + 律师 |
| 误导入或超范围数据 | 立即停止使用并删除 | `[[删除审批人]]` |
| 监管或司法机关要求 | 按法律文书执行 | 法务 |

3.1 删除触发条件：`[[删除触发条件]]`。
3.2 删除执行人：`[[删除执行人]]`；复核人：`[[删除复核人]]`。

## 4. 删除方式与顺序（需律师确认）

4.1 建议顺序：停止新的处理 → 删除临时库与导出暂存 → 删除数据库业务表 → 删除供方侧举证包副本 → 按轮换淘汰备份 → 出具删除记录。
4.2 审计链为追加式且被签名与链头保护，不能静默改写；删除审计记录会破坏链校验。审计记录的删除、脱敏或归档方式必须由律师确认。
4.3 数据库删除应按 run 或数据主体范围执行，避免误删其他 run 或无关客户数据；删除前应导出待删清单供复核。

## 5. 举证包不可变性与删除请求的冲突（需律师确认）

5.1 举证包的价值来自可验签、可重放与历史不可静默改写；一旦删除包内输入或结论，验签与重放将失败。
5.2 可选处理方式：
   - 方式 A：拒绝删除并说明法律依据与争议保全必要性；
   - 方式 B：删除包体，保留包外锚点、删除记录与必要的最小证明；
   - 方式 C：客户侧删除，供方不留副本，客户自行承担不可重放后果。
5.3 采用哪种方式、是否需要向数据主体说明、是否保留哈希与锚点，均需律师确认。本草案不预设结论。

## 6. 返还

6.1 合同终止或客户要求时，供方按 `[[返还方式]]` 返还客户数据与举证包；返还介质、加密方式与接收人：`[[返还介质与接收人]]`。
6.2 返还完成后，供方按第 4 条删除副本，法律要求保留的除外。

## 7. 备份与残留副本

7.1 备份轮换周期：`[[备份轮换周期]]`；备份介质位置：`[[备份介质位置]]`。
7.2 删除主数据后，备份中的残留副本应在下一个轮换周期内自然淘汰；如需立即清除，应说明技术可行性与成本。
7.3 离线介质、归档磁带与云快照是否属于“留存”，需律师与运维共同确认。

## 8. 删除记录与证明

8.1 每次删除应记录：删除对象、范围、执行人、复核人、时间、方式、结果与例外。
8.2 删除证明形式：`[[删除证明形式]]`；是否向客户出具：`[[是否出具删除证明]]`。
8.3 删除记录本身也是数据，其留存期限：`[[留存期限-删除记录]]`。

## 9. 例外（需律师确认）

9.1 法律要求保留、诉讼或争议保全、监管调查、审计需要等情形可暂停删除。
9.2 法律保留例外：`[[法律保留例外]]`；争议保全期限：`[[争议保全期限]]`。
9.3 暂停删除应有书面依据、范围与期限，不得以“可能有用”为由无限期保留。
