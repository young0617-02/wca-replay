# 合规材料目录（草案）

> **性质**：本目录下全部文件均为提交律师、法务与业务方审阅的草案，不是法律意见，不可直接签署、不可对外承诺。定稿前不得作为委托方交付物或制度发布。
>
> **版本口径**：本目录材料对应 **0.4.19** 交付（第二十一轮，8 个样例举证包）。文中出现的 0.4.17/0.4.18 仅为历史冻结版本与实际执行记录，不代表本材料适用于旧版；如引用旧版产物，须同时注明其与 0.4.19 的关系。

## 2. 统一占位符约定

2.1 所有待填内容使用 `[[...]]` 形式，例如 `[[委托方全称]]`、`[[处理目的]]`、`[[留存期限-原始输入]]`。
2.2 每份文件文末均有「待填空字段清单」，列明占位符含义与应由谁提供；不得用猜测值替代。
2.3 同一占位符在不同文件中含义一致；若委托方与受托方视角不同，应在文件中分别注明。

## 3. 使用流程

| 步骤 | 动作 | 责任方 | 产出 |
| --- | --- | --- | --- |
| 1 | 律师审阅条款与合法性判断 | 外部律师 | 批注或修订版 |
| 2 | 业务方填写主体、目的、期限、部署与联系人 | 业务方/委托方 | 填好的草案 |
| 3 | 委托方 HR/法务确认告知、同意与内部制度衔接 | 委托方 | 确认记录 |
| 4 | PIA 风险等级与可接受性确认 | 律师/业务方 | 评估结论 |
| 5 | 定稿并签署 | 双方授权代表 | 正式文件 |
| 6 | 归档并建立版本记录 | 业务方 | 版本台账 |

## 4. 事实基线

4.1 本目录的事实描述只取自 `docs/数据最小化方案.md`、`docs/安全与证据链现状.md` 与 `reports/四项未闭合事项-决策方案.md`，不另行推断。
4.2 技术现状：默认不裁剪输入；仅 `leave:paid` 可受控裁剪；导出已移除金额与录入人；问答按 run 过滤；数据库自增主键不进入投影；`emp_id`/`pseudonym`/`confirmed_by` 假名化与包内字段级加密未实现。
4.3 合规现状：无已签署 DPA、无已完成 PIA、无生效的留存删除策略、无定稿告知同意模板；样例数据全部为合成数据。

## 6. 维护规则

6.1 律师修订版应另存为独立文件或版本，不覆盖本草案原文；每次定稿保留版本号与日期。
6.2 若技术默认行为变化（如默认裁剪、假名化），必须同步更新 `05-包内个人字段盘点-草案.md` 与 `06-PoC不接真实数据声明-草案.md`。
6.3 本目录不修改代码、规则包、已交付包或 `handoff/` 下任何文件。
