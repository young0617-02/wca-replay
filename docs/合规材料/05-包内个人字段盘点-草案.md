# 举证包内个人字段盘点（草案）

> **草案性质**：本文件是内部字段盘点草案，供律师、委托方安全与隐私审阅；不是合规结论，也不替代《数据最小化方案》的技术判定。
> **需要律师确认的条款**：各字段是否属于敏感个人信息、薪酬与行踪字段的处理必要性、`reason` 等自由文本的敏感性、删除与假名化方案。
> **版本口径**：本盘点对应 **0.4.19** 交付（第二十一轮）；0.4.17/0.4.18 为历史冻结版本与执行记录，不再作为修改基线。
> **必须由业务方填空的字段**：`[[委托方全称]]`、`[[字段处置确认人]]`、`[[裁剪口径确认人]]`、`[[假名化密钥管理方式]]`、`[[敏感字段范围确认]]`、`[[跨包关联需求]]`；留存期限分类见《02-数据留存与删除策略-草案.md》§2，不在本文件填写。

## 1. 口径说明

1.1 标签沿用 `docs/数据最小化方案.md`：**规则必需**（规则/引擎读取，缺失会改变结论或使重放失败）、**仅展示**、**可派生**、**未被引用**（规则与引擎无读取点）。
1.2 “投影字段”指 `src/projection.py` 固定清单中的字段；投影字段缺失时导出直接报错，不静默降级。
1.3 “包内默认”指当前默认导出行为，不是建议值；默认不裁剪任何输入。
1.4 涉敏提示仅为业务与律师审阅线索，等级与定性需律师确认。

## 8. 处置建议（建议，不是结论）

8.1 对规则必需字段不做裁剪，避免改变结论或使重放失败。
8.2 对“未被引用但导入必填”的字段，先改导入器与表结构，再谈裁剪；且必须开新版本并重跑证据，不得在 0.4.19 交付版上直接改，更不得回改 0.4.17/0.4.18 已冻结版本。
8.3 对 `pseudonym`、`confirmed_by`、`note` 等身份或自由文本字段，优先评估假名化或按角色脱敏，其次才是删除；跨包关联需求需业务方确认。
8.4 对 `trip.destination` 与 `leave.kind`，需律师判断是否属于敏感信息，再决定保留或裁剪。
8.5 任何裁剪都必须记录 `omitted_fields`，并保留投影指纹与重放验证；不得静默截断。
