# 个人信息保护影响评估（PIA）提纲

> **草案性质**：本文件是提交律师与业务方共同填写的评估提纲，不是已完成的 PIA，不是法律意见，不可据此宣称“风险已清零”。
> **需要律师确认的条款**：第 3 条处理合法性基础与必要性比例、第 5 条风险等级与可接受性、第 7 条缺失控制是否构成禁止处理事由、第 8 条评估结论措辞、第 9 条复核与重新评估触发条件。
> **必须由业务方填空的字段**：评估负责人、评估日期、部署形态、处理地点、员工规模、处理目的、合法性基础、告知方式、留存期限、风险接受人、残余风险标准、复核周期。

## 1. 评估对象与边界

1.1 评估对象：工时合规裁决与举证层，包括考勤打卡、排班、请假、加班审批/审批台账、出差、更正数据的导入、规则计算、分级结论生成与举证包导出。
1.2 边界：本提纲覆盖个人信息处理活动本身；不评估规则条文的法律正确性（另见决策方案第 3 项），也不评估委托方内部处分制度的合法性。
1.3 当前阶段：PoC 使用合成数据；接入真实员工数据前须完成本评估并经律师审阅。
1.4 评估负责人：`[[评估负责人]]`；评估日期：`[[评估日期]]`。

## 4. 个人权益影响场景

| 场景 | 可能影响 | 现有缓解【事实】 | 剩余问题 |
| --- | --- | --- | --- |
| 误判导致处分或扣款 | 员工收入、名誉、劳动关系 | 分级结论、条文出处、人工确认链路、可重放举证 | 7 条 VIOLATION 无真实具名确认；确认人仍为演练身份 |
| 举证包外泄 | 工号、化名、薪酬、行踪、审批人暴露 | 签名、包外 pin、访问控制、导出移除金额与录入人 | 默认包内仍含 `pseudonym`、`normal_hourly_cents`、`confirmed_by` |
| 再识别 | 化名或设备号与外部数据关联 | `emp_id` 保留用于规则与责任追溯 | `emp_id`/`pseudonym`/`confirmed_by` 假名化未实现 |
| 跨包关联 | 多批次数据拼接出勤与行为画像 | 每次包按 run 范围收窄；问答按 run 过滤 | 包间关联仍可能；是否允许需业务与律师确认 |
| 历史包无法删除 | 数据主体删除请求与不可变证据冲突 | 签名与重放保证历史不可静默改写 | 删除策略未定，见留存策略第 5 条 |
| 离职员工数据 | 离职后仍留在历史包 | 按 run 留存 | 离职后的删除与保留规则未定 |

## 6. 现有控制措施【事实】

- 导出产物移除 `amount_cents_input`、`amount_entered_by`；数据库与复核台保留原值。
- `question_log` 按 run 关联，导出只收本 run；历史未关联行不进入包。
- 包内不使用数据库自增主键；来源定位用 `rel_path` 与 `line_no`。
- 两层指纹：`inputs_digest` + 签名保证输入字节；`projection_fingerprint` + `conclusion_digest` 保证结论可复算。
- 举证包支持 Ed25519 签名、外部公钥 pin、工件摘要与结论摘要校验。
- 包处理有路径穿越防护与资源上限，拒绝符号链接与硬链接。
- 写接口强制 CSRF；审批台账写入服务端校验权限。
- 受控裁剪仅 `leave:paid`，并在 manifest 记录 `omitted_fields`；投影字段缺失时导出报错。

## 7. 缺失控制【事实】

- 默认不裁剪输入，`pseudonym`、`normal_hourly_cents`、`approval.recorded_at` 仍保留。
- `emp_id`、`pseudonym`、`confirmed_by` 假名化未实现；包内字段级加密未实现。
- 无 DPA、无告知同意模板、无留存删除策略、无已完成 PIA。
- 包内仍含 `confirmed_by`、`note`、审批文号与附件哈希。
- 真实具名确认尚未落地，7 条 VIOLATION 无人工背书。
- 外部模型调用边界与子处理者名单未定。
