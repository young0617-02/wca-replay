# PoC 不接真实数据声明（草案）

> **草案性质**：本文件是供业务方、法务与律师审阅的声明草案，不是已生效的对外承诺，不是法律意见。
> **需要律师确认的条款**：声明措辞与责任限制、是否可作为对外交付文件、违反声明后的责任分配、与 DPA 的关系。
> **必须由业务方填空的字段**：声明主体、声明日期、有效期、委托方全称、联系人、授权代表、真实数据试点的书面条件。

## 1. 声明正文（草案）

**关于工时合规裁决与举证层 PoC 不接入真实员工数据的声明**

声明主体：`[[声明主体]]`
声明日期：`[[声明日期]]`
有效期：`[[声明有效期]]`

1. 本声明适用于软件版本 **0.4.19** 及其随第二十一轮交付的 8 个样例举证包。该版本是验证工具与样例包的 PoC，不构成合规结论，不可作为生产就绪依据。0.4.17/0.4.18 为历史冻结版本，本声明不适用于旧版。
2. 当前全部样例数据均为合成或匿名演示数据，不含任何真实员工的考勤、薪酬、请假、出差或审批信息。
3. 未经 `[[声明主体]]` 书面同意并完成前置合规程序，任何委托方、受托方或接收方不得将真实员工数据导入本系统，不得用本系统对真实员工生成处分、结算、绩效或合规结论。
4. 如委托方要求开展真实数据试点，须同时满足：签署数据处理协议、完成个人信息保护影响评估、确定留存与删除策略、确认告知与合法性基础、补齐真实具名确认流程，并以书面变更或补充协议约定范围与期限。
5. 违反本声明导入真实数据所产生的责任，由导入方承担；`[[声明主体]]` 不承担因委托方超范围使用产生的责任。
6. 本声明不替代律师意见，不构成对任何法律责任的免除；具体责任限制以正式合同为准。

## 2. 技术现状附录（事实）

| 项目 | 当前状态 |
| --- | --- |
| 默认输入裁剪 | 默认不裁剪任何输入字段 |
| 包内可见字段 | `pseudonym`、`normal_hourly_cents`、`confirmed_by`、`note`、审批文号与附件哈希等 |
| 受控裁剪 | 仅 `leave:paid` 可在显式开关下裁剪，并记录 `omitted_fields` |
| 假名化 | `emp_id`、`pseudonym`、`confirmed_by` 假名化未实现 |
| 包内加密 | 字段级加密未实现 |
| 导出侧收窄 | 已移除 `amount_cents_input`、`amount_entered_by`；问答按 run 过滤；数据库自增主键不进入投影 |
| 签名 | Ed25519 v3；外部 pin 只证明与供给公钥匹配，不证明来源主体身份 |
| 具名确认 | 样例包内 2 条“已确认结论”的确认人为演练身份，不覆盖 7 条 VIOLATION |
| 合规文件 | 本目录为草案，DPA、PIA、留存删除策略与告知同意模板均未定稿、未签署 |

2.1 上述技术状态来自 `docs/数据最小化方案.md` 与 `docs/安全与证据链现状.md`，不因本声明而改变。
2.2 若后续版本改变默认裁剪或假名化行为，应更新本声明并开新版本，不得沿用旧声明。

## 3. 允许与禁止的使用

| 场景 | 是否允许 | 条件 |
| --- | --- | --- |
| 内部演示、培训、产品介绍 | 允许 | 使用合成样例数据 |
| 委托方现场 PoC 演示 | 允许 | 使用合成样例数据；不导入委托方真实数据 |
| 委托方内网部署演示 | 允许 | 数据仍为合成；网络与访问控制由委托方负责 |
| 真实员工数据试点 | 须书面同意 | 完成第 1 条第 4 项全部前置条件 |
| 生成处分、结算、绩效或合规结论 | 禁止 | 除非完成正式合规程序并以合同另行约定 |
| 向监管或第三方作为合规证明 | 禁止 | PoC 输出不构成合规结论 |
