## 1. 统计口径与图例

### 1.1 条文计数口径

- 按 `citation_id` 唯一计数；同一部法规的不同条分别计一行。
- 「动态地方条文」单独说明：`OT-D01`、`OT-D02`、`OT-D03`、`WK-W01` 这四条「报酬类」规则，会按员工所在城市档位动态追加地方倍数条文和国家层面附加条文；`RULE-PACK.md` 只列基础条文，不列动态追加部分。
- 内部合成制度 `policy.sz.*` 不是法律、行政法规、部门规章或司法解释，单列并标注「非法规」，不计入「法规/通知」数量。

### 1.2 包内呈现方式

| 标记 | 含义 |
|---|---|
| **仅条号** | 包内只有 citation_id / 法规名称 + 条号，或只有一句标题性标签；没有该条要旨的展开。 |
| **条号+摘要** | 包内另有单句要旨、阈值说明或一句内容概括，但**没有复制原文**。 |
| **有全文** | 包内复制了该条全文。本次核查结果：**0 项**。 |

### 1.3 映射状态

| 标记 | 含义 |
|---|---|
| **直接依据** | 条文直接规定该规则判断的事实、阈值或法律后果。 |
| **间接依据** | 条文主要规定制度效力、休息权保障等背景，不直接规定该规则的事实。 |
| **映射待确认** | 条文与规则事实之间缺少直接对应，或存在年度、款号、版本不一致；**不得当作已确认的法律依据**，需法务书面确认。 |
| **动态追加** | 由城市档位配置在运行时追加，不在 `RULE-PACK.md` 基础表中。 |
| **非法规** | 企业内部合成制度，不能进行官方核验。 |

### 1.4 官方一手文本可获取性

| 标记 | 含义 |
|---|---|
| **可获取（官方页面）** | 仓库记录显示有官方政府网站/官方数据库全文页。 |
| **有限可获取** | 官方页面存在但入口不稳定、字段空白或只有政府转载，需要人工核验。 |
| **不适用** | 企业内部制度或合成样本，没有官方来源。 |
| **未实时复核** | 本次编制未联网确认链接当前是否可访问。 |

### 1.5 现行有效性

本清单**不对任何条文下「现行有效」结论**。每一行都写「需核验」，并给出核验方法。核验方法代号：

| 方法 | 适用对象 | 操作 |
|---|---|---|
| **A** | 法律 | 在 `flk.npc.gov.cn` 以法规名称检索 → 核对「现行有效/失效」状态、公布日期、修正日期、条号 → 与中国人大网、人社部官方全文页、全国人大常委会公报三方比对 → 记录核对日期、URL、页面存档或截图。 |
| **B** | 行政法规 | 在 `xzfg.moj.gov.cn` 检索 → 核对发布令号、修订决定、施行日期、有效性状态 → 与国务院公报比对。 |
| **C** | 部门规章/规范性文件 | 在 `mohrss.gov.cn` 规章库检索 → 核对「是否有效」字段、废止或修改决定 → 查国务院/人社部公报 → 字段空白时向发布机关书面确认。 |
| **D** | 地方性法规 | 在省/市人大常委会公报、地方政府法规库检索 → 核对最新修正决定、施行日期、条号连续性 → 与现行官方文本比对。 |
| **E** | 国务院办公厅年度通知 | 每年 11–12 月在中国政府网政策文件库核对下一年度通知 → 核对文号、发布日期、放假区间、调休上班日、法定节假日当天。 |
| **F** | 企业内部制度 | 企业提供盖章制度、民主程序与公示证据 → 与劳动合同/员工手册比对；无法外部核验。 |

## 9. 维护机制建议

### 9.1 角色与职责

| 角色 | 职责 | RACI |
|---|---|---|
| 法务/合规负责人 | 跟踪法律、行政法规、部门规章、地方性法规、司法解释、年度通知；核对原文与效力状态；签署核对记录；判定是否构成「实质变化」 | **A/R** |
| 规则包维护者（工程） | 评估影响规则、阈值、事实认定；实现新规则包；跑测试与回放；维护 `RULE-PACK.md`/`LAW-REFERENCES.md` | **R** |
| 产品/交付负责人 | 批准切换日；通知使用方；确认是否对外发布新版本 | **A** |
| 交付/运维 | 发布、归档、链接巡检、保留旧 wheel/旧包/旧锚点 | **R** |
| 第三方律师/审计 | 独立复核本清单与抽样包；对「映射待确认」项出具意见 | **C/I** |

> R=负责执行，A=最终批准，C=被咨询，I=被告知。

### 9.2 核对频次与触发条件

| 对象 | 频次 | 触发条件 | 时限建议 |
|---|---|---|---|
| 法律（《劳动法》《劳动合同法》） | 每季度一次 | 全国人大/常委会修正、废止、新解释、官方数据库状态变化 | 发现后 30 天内完成影响评估 |
| 行政法规（工时规定、放假办法） | 每季度一次 | 国务院令、修订决定、施行日期变化 | 30 天内 |
| 部门规章（503 号、489 号） | 每半年一次 | 人社部废止/修改/替代、规章库有效性字段变化 | 60 天内 |
| 地方性法规（深圳、广东工资支付条例） | 每季度一次 | 市人大常委会/省人大常委会修正公告、地方人社局新口径 | 60 天内 |
| 国务院办公厅年度节假日通知 | 每年 11–12 月一次 | 下一年度通知发布 | 发布后 5 个工作日内更新 |
| 企业内部制度（合成/真实） | 企业制度变更时 | 员工手册/考勤制度/审批制度修订、民主程序或公示变化 | 变更后 30 天内 |
| 链接可用性 | 每季度一次 | URL 失效、页面迁移、域名变更 | 发现后 10 个工作日内替换或按文号检索 |

### 9.3 发现修订后的处理流程

1. **登记**：填写变更单，至少包含 `citation_id`、法规名称、条号、旧文本摘要/新文本摘要（不复制大段原文）、公布日期、施行日期、来源 URL、核对人、核对日期、影响规则 ID。
2. **法务复核**：判断是「实质变化」还是「非实质变化」。
   - 实质变化：条号、条文内容、效力状态、施行日期、地方口径、年度日历发生变化，且可能影响阈值、事实认定或结论。
   - 非实质变化：仅链接、排版、标题、页面迁移，不影响条文内容。
3. **影响评估**：规则包维护者列出受影响规则、测试用例、历史包回放影响；确认是否需要改判据、改 explanation、仅更新文档。
4. **新规则包版本**：实质变化必须新建规则包版本（如 `rp-YYYY.MM.<region>.vN`），**不得直接修改旧规则包**，不得静默改写旧审计链或重置 genesis。
5. **测试与回放**：新版本跑全量测试；旧包用旧规则包 + 对应 wheel 回放；确认旧包 `conclusion_digest` 不变、`wca-verify`/`wca replay` 通过。
6. **批准与切换**：产品/交付负责人批准切换日；明确切换只影响切换日后新启动的 run；切换前已启动的 run 按启动时规则包。
7. **发布与通知**：更新 `RULE-PACK.md`、`LAW-REFERENCES.md`、本清单、交付 README；通知使用方与律师；记录切换事件（`prev_rule_pack_version`、`rule_pack_version`、`switched_at`、原因、批准人）。
8. **归档**：旧规则包、旧 wheel、旧包、旧 `policies/` 快照、旧锚点全部保留；不重签、不覆盖。

### 9.4 规则包版本与切换日

- **版本号**：沿用现有 `rp-YYYY.MM.<region>.vN` 命名；新版本号必须与内容版本、包内 `producer.rule_pack_version` 一致。
- **切换日**：由产品/交付负责人批准；写入纪元/切换事件；不得用「当前时间」隐式切换。
- **旧包**：按包内 `rule_pack_version` 回放；不得用新规则包重算旧包；不得改写旧 finding 的 `rule_version`。
- **默认规则包**：活动库默认规则包切换必须单独确认；未确认前不得改变默认值。
- **文档同步**：`RULE-PACK.md`、`LAW-REFERENCES.md`、本清单、`README` 的版本说明必须同步；不得只改包内副本而保留旧生成模板。

### 9.5 旧版本保留与回放

- 保留旧 wheel、旧包 zip、旧 `policies/` 快照、旧锚点、旧 `SHA256SUMS` 与签名文件；旧包不重新签名。
- 回放命令以包内 `producer.version` 匹配 wheel 版本；版本不一致时按现有规则失败关闭（`PRODUCER FAIL`），不得放宽。
- 旧包回放前先跑 `wca-verify`；确认 `RESULT OK` 或按已知状态说明；不得把 `PARTIAL` 当 `OK`。
- 旧包只读；不得为了让新规则通过而修改旧包字节、旧 `conclusion_digest` 或旧审计链。
- 归档目录按版本独立；新版本新目录，不覆盖 `dist/wca-replay-*` 或已交付 `handoff/` 目录。

### 9.7 无法核验时的降级规则

- 无法取得官方一手文本，或官方库「是否有效」字段空白：该条文在对外结论中只能标「需核验」，相关 finding 不得表述为「已确认违法」；应按现有规则降级为 `REVIEW`/`DEFENSIBLE`。
- 条文与规则事实缺少直接对应（本清单第 7 节）：不得把该条文写成直接依据；应在 explanation 中写明「背景/间接依据」，或改引更贴切的条文。
- 年度通知未覆盖校验年度：明确写「年度日历未收录」，不得用相邻年度通知代替。
- 内部合成制度：不得当作真实企业制度；使用方交付时必须替换为企业盖章制度与民主程序证据。

## 10. 边界与免责

1. **本清单不替代律师意见，不构成法律意见，不判定任何行为违法。** 具体案件应咨询执业律师，并以律师核对当日官方文本为准。
2. **不复制大段法条原文。** 本清单只给法规名称、条号、来源类型和获取途径；原文请打开官方页面核对。这样既降低准确性和版权风险，也避免清单本身成为「二手文本」。
3. **「可获取」不等于「已实时核验」。** 本次编制依据仓库 2026-10-08 的核对记录，未重新联网确认所有链接当前可访问；链接可能失效、页面可能迁移，律师应按法规名称/文号检索替代入口。
4. **「现行有效」不作结论。** 所有条文均写「需核验」；「未见废止」不等于「现行有效」，「官方库字段空白」也不等于「有效」。
5. **`policy.sz.*` 是合成样本制度，不是真实企业制度，不能作为法律依据。** 使用方交付时需替换为真实制度，并保留民主程序/公示证据。
6. **未引用司法解释。** 如使用方需要最高人民法院司法解释层面的依据，本清单不覆盖，需另行补充。
7. **「映射待确认」项不得当作已确认。** 第 7 节列出的项目需法务书面确认后，才能写入规则包、`LAW-REFERENCES.md` 或对外结论。
8. **本清单不改变规则包、不改变已交付包、不改变回放链。** 仅作为检索索引和维护机制建议；0.4.17 的包字节、摘要、签名均不受影响。
