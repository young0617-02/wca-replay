# 数据最小化方案（M-02）

> 目标：把举证包承载的个人信息逐字段说清，先做不改变结论、不破坏 replay 的零风险部分；其余进入待定清单。本文不是合规结论，也不声称“已满足”任何外部要求。

## 1. 标签与判定口径

- **规则必需**：规则/引擎读取，缺失会改变 `conclusion_digest` 或让 replay 无法复算。
- **仅展示**：只用于页面/报告展示，不进入规则结论。
- **可派生**：可由其他字段或规则计算得到，删除不增加信息。
- **未被引用**：在 `src/rules/`、`src/engine.py` 中没有任何读取点；必须有 grep 证据。

代码位置引用均指当前工作区；输入文件字段是否“可删”还受 `input_fingerprint` 与 replay 约束，见第 3 节。

## 3. 两层指纹设计（本轮新增）

| 层 | 字段 | 证明什么 | 不证明什么 |
|---|---|---|---|
| 字节层 | `inputs_digest` + `manifest.signature` | `inputs/` 下实际文件（含 `inputs/manifest.json`）字节与来源；改一个字节/换文件会 `INPUTS FAIL` 或签名失败 | 不证明结论正确；不证明输入能复算出该结论 |
| 字段层 | `projection_fingerprint` + `conclusion_digest` | 规则/引擎读取的字段规范化后能复算出同一结论；非投影字段变化不影响它 | 不证明原始字节未被换（那由上一层负责） |
| 旧指纹 | `input_fingerprint` | 保留原语义：run 时原始输入整包（rel_path/sha256/rows/kind + scope）；旧包继续按此 replay | 不再要求裁剪后的新包与它相等 |

**投影字段清单**（固定于 `src/projection.py:PROJECTION_TABLE_FIELDS`）：

| 输入/表 | 投影字段 |
|---|---|
| employee | `emp_id,job_code,org_id,region_code,worktime_regime,contract_approved_flex` |
| punch | `emp_id,event_ts,punch_type,device_id` |
| correction | `emp_id,claimed_ts,claimed_type,reason,approved`（reason 经 QUAL-EMPTY→QUAL-01 间接进入结论） |
| leave | `emp_id,leave_kind,start_ts,end_ts,approved`（不含 `paid`） |
| trip | `emp_id,start_ts,end_ts`（不含 `destination`） |
| schedule | `emp_id,work_date,planned_start,planned_end,rest_minutes` |
| approval（v5/v6） | `emp_id,doc_no,regime,valid_from,valid_to,job_codes,region_code,attachment_sha256`（不含 `recorded_at/version_no/published_at`） |
| ingest_issue | `rule_id,severity,emp_id,work_date,field_name,raw_value,line_no`（`file_id` 为数据库分配序号，不入投影） |

规范化：时间统一为带 `+08:00` 的分钟精度；日期 `YYYY-MM-DD`；整数保持整数；`job_codes` 解析为升序字符串列表；sha256 小写；空值为 `null`；每张表按固定列顺序 + 固定 `ORDER BY` 生成行数组，再做 canonical JSON + SHA-256。字段顺序/行插入顺序/时间格式差异不改变结果；列大小写与业务值原样保留。

**投影范围**：导出/重放都按本次包内 `rel_path` 与本次 run 的 `emp_ids` 过滤事实/质量/审批表，避免把其他 run 的行算进投影；`inputs/manifest.json` 目前只登记文件/行数，不登记列，列级安全由投影清单 + `OMITTABLE_FIELDS` 决定，裁剪结果显式记入 `omitted_fields`。

**裁剪规则**：只有同时在 `OMITTABLE_FIELDS`（当前仅 `leave.paid`）且不在 `PROJECTION_INPUT_FIELDS` 的列才允许裁剪；`omitted_fields` 写入 manifest 与 `inputs/manifest.json`；投影字段缺失在导出阶段直接 `ValueError`。当前 `employee.pseudonym`（按要求保留）、`normal_hourly_cents`、`approval.recorded_at` 仍未被导入器安全接受，开关不会启用它们。默认开关为空，不计算/不写投影指纹，导出字段与既有 replay 语义保持不变。

**分工**：`verify.py` 校验字节层（`inputs_digest`、签名、逐文件哈希、结论集哈希），**不重算投影**（它不跑引擎）；`replay` 在导入并重跑后重算投影指纹，缺失/不一致输出 `PROJECTION FAIL`。新包若声明 `omitted_fields`，`input_fingerprint` 会与 manifest 不同，这是预期，不是回归；旧包无投影字段时按旧三元组语义。

## 4. 选项与三件事的影响

> **红** = 会改变 `conclusion_digest`，不进入本轮代码；**指纹** = `input_fingerprint` 是否改变；**旧包 replay** = 历史包是否仍可 replay；**新包 replay** = 采用该选项后新导出的包能否 replay。

| 选项 | 指纹 | conclusion_digest | 旧包 replay | 新包 replay |
|---|---|---|---|---|
| 直接移除 `pseudonym`（仅展示） | 变（输入 CSV 字节变） | 不变 | 仍可 | **失败**，除非重算包内指纹；本轮不做 |
| 直接移除 `normal_hourly_cents` / `leave.paid` / `approval.recorded_at` | 变 | 不变（规则不读） | 仍可 | **失败**，且导入必填/校验会拒；本轮不做 |
| 直接移除 `device_id` / `job_code` / `region_code` / `regime` | 变 | **红：会变** | 仍可 | 可能改变结论；不做 |
| 工号/姓名 HMAC 假名化（`emp_id` 或 `pseudonym`） | 变 | `emp_id` 假名化**红**；只改 `pseudonym` 不变 | 仍可 | 只改 `pseudonym` 仍因指纹不同失败；`emp_id` 假名化会改变结论；本轮不做 |
| 金额区间化/等级化 | 打印产物变，输入指纹不变 | 不变 | 仍可 | 仍可；本轮采用“移除金额字段”而非区间 |
| 保留但加 ACL / 会话身份 | 不变 | 不变 | 仍可 | 仍可，但包离开系统后仍含原文；依赖部署 |
| 包内字段级加密 | 输入指纹/输入摘要会变 | 不变 | 仍可 | 需解密后再 replay；密钥分发复杂；本轮不做 |
| 移除导出 `amount_cents_input` / `amount_entered_by` | 不变 | 不变 | 仍可 | 仍可；本轮做，DB 保留 |
| `question_log` 按 run 过滤 | 不变 | 不变 | 仍可 | 仍可；本轮做，新增 `question_log.run_id` |

## 5. 推荐组合

**默认配置（本轮）**

1. 原始输入 CSV 一律保留，不删字段、不改值；`pseudonym`/`normal_hourly_cents`/`leave.paid`/`approval.recorded_at` 只进入待定清单。
2. 导出产物移除 `amount_cents_input`、`amount_entered_by`；数据库与复核台保留原值，包内不再出现金额和录入人。
3. `question_log` 增加 `run_id` 关联，导出只收本 run 记录；历史未关联行不进入任何包。
4. 保留 `confirmed_by`、`note`、`emp_id`、审批文号等责任/规则字段，交付时用 ACL、包外 pin 与四元组控制访问。

**可选更严格配置（需另行确认，不在本轮代码）**

- 对 `pseudonym`、`actor_emp_id`、`confirmed_by` 做 HMAC-SHA256 假名化，保留跨包关联但去掉可识别性；代价是输入指纹/包内指纹需要重算，跨包关联需要密钥管理。
- 对 `leave.paid` 可在受控开关下裁剪（已有投影指纹 + replay 测试）；`normal_hourly_cents`/`recorded_at` 仍被导入必填/表结构约束，需先改导入器。
- 对金额采用区间/等级而非直接移除；代价是责任区块失去精确金额，需确认接收方是否接受。

## 7. 本轮零风险实现与待定清单

- 已实现：`question_log.run_id` 关联 + 导出按 run 过滤；导出产物移除金额/录入人字段；两层指纹（`projection_fingerprint` 默认计算并写入 manifest，`input_fingerprint` 语义不变）；受控开关 `omit_fields`（默认空，当前只允许 `leave:paid`）。
- 默认不裁剪任何输入：`pseudonym`、`normal_hourly_cents`、`approval.recorded_at` 仍保留；其中 `leave:paid` 可在显式开关下裁剪并 replay，其余仍受导入必填/表结构约束。
- 未实现（待定）：`emp_id`/`pseudonym`/`confirmed_by` 假名化、包内加密、金额区间化；输入副本裁剪的更大范围仍要先解决导入必填字段与指纹设计。
- 不改 `conclusion_digest`、不改变既有包 replay；裁剪后的新包 `input_fingerprint` 必然不同，由 `projection_fingerprint` + `conclusion_digest` 判定，不把旧包基线当 bug。
