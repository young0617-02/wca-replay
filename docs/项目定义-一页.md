# 项目定义（一页）· 举证级工时合规校验与制度问答 Agent

> 版本 v1.0 ｜ 2026-10-08 ｜ 本页是项目的"门牌号"，细节以 `需求文档-用户故事.md` 为准；两者冲突时以需求文档 §6/§7 为准。

## 一句话定义

> 为**中小企业里管考勤的 HR 专员与需要为结论签字的 HR 负责人**，在**月度工时核算与加班争议举证**这个场景下，解决**"拿不出一条可复核、可追溯、有法条出处的工时链，而 AI 给的结论又不敢直接对外"**这个问题，通过**确定性规则引擎算工时 + 带权限下推与出处引用的检索增强问答 + 置信度门禁与人工确认闭环**这套 AI 能力，达到**错承诺 0 条、越权召回 0 条、每条结论可被外部仅凭导出材料重放复现、且每个指标数字都能被第三方在干净环境无凭证复跑**的结果。

## 目标用户

| 用户 | 用来做什么 | 为什么是他 |
|---|---|---|
| **HR 专员**（主操作者） | 导入打卡/请假数据、看异常报表、发起校验、导出举证包 | 数据来路只有他清楚，异常处置也落在他手上 |
| **HR 负责人**（决策与签发者） | 复核"需复核/明显违规"异常、录入金额并具名、签发举证包 | 责任必须落到一个有名有姓的人，这是本项目的立命之处 |
| **普通员工**（只读自助） | 查本人工时结论、查制度与法条依据 | 争议的另一方，也是 ACL 权限模型的验证者 |
| **外部接收方**（不登录） | 仅凭举证包离线复核每条结论 | 业务价值的真正落点：能不能被仲裁/审计采信 |
| **复跑评审者**（读仓库） | 干净环境跑测试与评测、核对每个数字的口径 | 作品集目标的真正落点，也是本项目唯一的真实用户 |

## 核心场景

- **场景 A｜月度核算与举证**：HR 专员上传 CSV → 系统拦脏数据 → 按城市档位（广州/深圳）与规则版本跑标准工时校验 → 异常三级分类（可申辩/需复核/明显违规）→ HR 负责人复核并具名 → 一键导出举证包。
- **场景 B｜制度问答**：任一角色在界面提问 → 权限谓词在**检索层**下推 → 答案带可点开出处（条文号 + 生效日期 + 地域层级 + 版本）与证据覆盖率 → 涉及金额时**只解释规则、不报数额**并转人工 → 全程留痕。
- **输入**：四类 CSV（打卡/请假/出差/补卡，**全部合成**）+ 制度/法条知识库条目。
- **输出**：分级异常清单（含规则 ID + 条文号）+ 举证包（审计日志 hash 链 + "规则版本 + 输入指纹 + 结论"三元组 + 责任标注）+ 带出处的问答（**不含任何金额**）。

## 痛点：现在怎么做，为什么不够

| 现在的做法 | 不够在哪 |
|---|---|
| Excel 手算加班 + 手工核对打卡 | 口径随人变、无版本、无留痕，事后说不清当时按什么算的 |
| 钉钉/飞书等平台的通用问答与审批 | 解决"有没有人应答"，不解决"这条结论能不能被第三方复核" |
| 直接把大模型接进考勤数据上问"该付多少" | LLM 会算钱、会编倍数、无出处、无责任人——**在劳动争议里反而是不利证据** |
| 只发"异常提醒"不做输出物 | 提醒不是证据；企业到仲裁时手里仍然没有链 |

**本项目的取舍**：AI 不碰钱、不签结论。它只做检索、解释与叙述；数值由规则代码算，金额由人录并由人签名。

## 成功指标（全部自测，不设外部百分比）

| 类型 | 指标 | 目标 | 怎么量 |
|---|---|---|---|
| 业务·红线 | **错承诺条数**（AI 单方给出金额） | **0** | 金额类子集全量跑 |
| 业务·红线 | **ACL 越权召回命中数** | **0** | ≥10 组变体直连接口 |
| 业务·可举证性 | 举证包**重放结论一致率** | **100%** | 只给包内三元组 + 原始 CSV 重跑比对 |
| 业务·可举证性 | 异常记录带规则 ID + 条文号的比例 | **100%** | 报表扫描 |
| 技术·检索 | 意图 Top-1、Hit@5 | 实测值，口径随数字写出 | ≥60 条三档评测集 |
| 技术·链路 | 工具调用成功率、引用忠实率、幻觉率 | 实测值（幻觉率设红线） | 判分器 + 人工抽检 |
| 技术·判分可信 | **变异捕获 ≥5/5**，还原后基线哈希一致 | 达标 | 注入真实缺陷逐个重跑 |
| 技术·性能 | 检索段 P95 / 端到端 P95（云 API 档）/ 导出 1,000 行 | 设计值 ≤500ms / ≤4s / ≤3s，**须实测后标三态** | 分段计时 |
| 成本 | 每问 token 三段分布（prompt / context / 工具调用）+ 真实账单 | 数字与账单可查 | 云 API 账单回填 |
| 可用性 | 评审者无云凭证 `pytest -m "not llm"` 一次全绿 | 达标 | 干净 venv 复跑 |

> **明确不设的指标**：效率提升 X%、节省 X 成本、拦截率、真实用户满意度。**理由：无真实用户、无真实流量、无客户**——这类数字我给不出分母，写了就是造假。

## 约束（不可谈判）

1. **人日**：总计 **19.5 人日**（1.5 人日/周 × 13 周 ≈ 0.93 人月，单人自主）。超支只能砍范围，不能加时。
2. **数据**：全程**合成数据**，不含任何真实个人信息（PIPL：行踪、生物识别须单独同意）；生成器固定种子可复现。
3. **口径来源**：**无 HR 访谈**，字段语义只从公开资料取；**禁写"已与 HR 核对"**，取不到公开依据的字段须显式标"自定义"。
4. **地域与工时制**：城市仅广州、深圳；工时制仅**标准工时（8 小时制）**。
5. **模型与部署**：云 API 后端（密钥只在 `.env`，不入仓库/日志/举证包，不外发身份与原始打卡行）；SQLite 单文件、无容器；界面 2.5 人日硬顶、不引前端框架。
6. **主体现实**：个人无企业主体 → 不开票、不做多租户、不对接平台、不宣称上线。
7. **时间线**：P0 闸门在 W1 末判定，判据不达标即整体停手切换方向。

## 非目标（明确不做）

多租户 SaaS / 审批流引擎 / 线上申辩流 / 排班优化求解 / **加班费金额自动计算** / 社保薪酬 / **综合计算工时与不定时的周期超额校验** / 完整考勤计算引擎 / 考勤硬件对接 / 私有化部署与等保备案 / 前端框架与图表看板 / 真实客户与"上线、在用、覆盖 XX 人"表述 / 训练或微调模型。

## MVP 最小闭环

**一条链跑通即成立**：
上传 CSV → 质量门禁拦脏 → 按城市档 + 规则版本做标准工时 6 类判据校验（引擎不产出金额）→ 异常三级带条文号 → HR 负责人界面复核并具名签发 → 导出举证包 → **外部方仅凭包内材料重放，结论逐条一致**；
同一份数据与条文支撑问答链（带出处、金额只解释、低置信转人工），全部指标由 ≥60 条三档评测集与变异测试证明其可信。
