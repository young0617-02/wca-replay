# 审批台账 P0：界面与权限方案

> 状态：已实现（2026-11-03，REV-28/REV-29）。本文件把网页入口的权限矩阵、CSRF、上传限制、
> 审计事件、发布加锁与边界写进仓库；实现以 `src/web/routes.py`、`src/rules/approval_docs.py` 为准。
> 活动库 `wca_worktime` 未执行任何写入；页面/接口只按当前配置的库工作。

## 一、路由与视图

### 只读（AU 与 AD 均可）
| 路由 | 内容 |
|---|---|
| `GET /approvals` | 批文列表：状态、文号、标题、工时制、生效期、版本数、当前版本 |
| `GET /approvals/{doc_no}` | 批文详情：版本链、状态、生效期、岗位/城市、org/employee scope、附件 SHA-256、发布人/时间 |
| `GET /approvals/coverage` | 按 `emp_id` 查 `employee_approval_coverage` 覆盖投影 |

### 写入（仅 AD）
| 路由 | 内容 |
|---|---|
| `GET /approvals/new` | 新建草稿表单 |
| `GET /approvals/{doc_no}/edit` | 编辑 DRAFT 版本表单 |
| `GET /approvals/import` | CSV 批量导入页 |
| `POST /api/approvals/draft` | 新建草稿 |
| `POST /api/approvals/{doc_no}/edit` | 编辑草稿（只允许 DRAFT） |
| `POST /api/approvals/{doc_no}/publish` | 发布，复用 `publish_doc` 加锁/冲突检测 |
| `POST /api/approvals/import` | CSV 批量导入（整批校验、单事务） |

## 二、权限矩阵

| 动作 | AU | AD | 未登录 |
|---|---|---|---|
| 列表 / 详情 / 覆盖 | 200 | 200 | 401 |
| 新建页 / 编辑页 / 导入页 | **403** | 200 | 401 |
| 新建/编辑/发布/导入 POST | **403** | 200（需 CSRF） | 401 |

- 权限在服务端：页面 `require` + service 层 `require_write` 双重校验；不依赖前端隐藏按钮。
- 所有写操作要求 AD；AU 即使拿到有效 CSRF token，POST 仍 403。

## 三、CSRF（全站会话写接口）

### 盘点
| 写接口 | 认证方式 | CSRF |
|---|---|---|
| `POST /login` | 无会话（登录前） | **豁免**：没有会话可绑定；登录本身不改变业务数据 |
| `POST /logout` | 会话 | 强制 |
| `POST /api/import` | 会话（OP/AD） | 强制 |
| `POST /api/check` | 会话（OP/AD） | 强制 |
| `POST /api/review/{id}/decision` | 会话（RV/AD） | 强制 |
| `POST /api/export` | 会话（OP/RV/AD） | 强制 |
| `POST /api/ask` | 会话（任意登录角色） | 强制 |
| `POST /api/approvals/draft` | 会话（AD） | 强制 |
| `POST /api/approvals/{doc}/edit` | 会话（AD） | 强制 |
| `POST /api/approvals/{doc}/publish` | 会话（AD） | 强制 |
| `POST /api/approvals/import` | 会话（AD） | 强制 |

- 读接口 `GET /ask`、`GET /evidence/{run_id}`、`/api/session` 和页面 GET 不要求 CSRF。
- **无 API 令牌认证路径**；CLI 不是 HTTP 会话通道，不做 CSRF（本机命令行由操作者直接执行，权限边界由 service 层与角色参数控制）。
- 因此：**会话写接口无豁免；唯一豁免是未建立会话的 `POST /login`**。

### 机制
- `app_csrf` 按会话 `sha256(会话令牌)` 绑定，只存 `sha256(CSRF token)`，**不存明文**。
- 页面 GET 签发/复用 token：优先复用浏览器 `wca_csrf` cookie（SameSite=Strict），
  且必须与库中哈希一致；否则生成新 token 并更新哈希。
- 页面通过 `<meta name="csrf-token">` 下发；前端 `wcaPost` 统一读取并放 `X-CSRF-Token`。
- 服务端从 header 或 JSON 的 `csrf_token` 取 token，只与库中哈希比对；缺失/错误/过期一律 403，
  **不写库、不产生副作用**。
- 登录/退出会删除 CSRF 记录；会话过期时同时清理 `app_session` 与 `app_csrf`。
- 旧库若存在 `app_csrf.csrf_token` 明文列，`init_db` 会整表重建为 `csrf_hash`，旧明文不保留；
  旧会话下一次 GET 自动获得新 token，不影响登录态。

## 四、CSV 上传限制

| 项 | 值 | 超限行为 |
|---|---:|---|
| 字节上限 | **1 MiB**（1,048,576） | 413，明确提示“请拆分，不截断” |
| 数据行上限 | **2,000 行** | 400，明确提示“请拆分，不截断” |
| 缺列 | 13 个必需字段 | 400，列出缺列 |
| 文件名 | `<名称>.csv` | 400，拒绝路径穿越 |
| 失败写入 | `import_drafts_csv` 整批校验 + 单事务 | 任一行非法回滚全部，不留半份台账 |

## 五、审计事件

| 动作 | action | 关键 payload |
|---|---|---|
| 新建草稿 | `approval_doc.draft` | doc_no、version_no、regime、scopes |
| 编辑草稿 | `approval_doc.draft.edit` | doc_no、version_no、期限、scopes |
| CSV 导入 | `approval_doc.import` | file_sha256、rows、docs、doc_nos、versions |
| 发布 | `approval_doc.publish` | doc_no、version_no、覆盖员工数、regime、期限 |

- actor 统一为 `human:<username>`；不写匿名“系统自动通过”。
- 审计事件与业务写入同事务；发布/编辑在锁区间内完成。

## 六、发布加锁与冲突

- 发布复用 `publish_doc`：SQLite `BEGIN IMMEDIATE`；PostgreSQL `pg_advisory_xact_lock(hashtext('wca.approval.publish'))`。
- 冲突检测与覆盖投影写入在同一锁区间；同员工同工时制重叠覆盖返回 `ApprovalConflictError`（Web 409）。
- 编辑草稿复用同一 PG advisory lock，避免“编辑范围/期限”与“发布展开”竞争。

## 七、边界（明确不做）

1. **不做附件原件上传**：仍只登记 64 位 SHA-256，不存文件、路径或 BLOB。
2. **只允许编辑 DRAFT**：已发布/已替代版本不可改写；给已发布批文加版本需新建同文号、递增版本号的草稿。
3. **CSV 上限 1 MiB / 2,000 行**：超限拒绝，不分卷、不流式截断。
4. **只做审批台账页面**：不提供外部审批 HTTP API、审批工作流或消息通知。
5. **不改变员工申报工时制**：批文/覆盖投影只用于 REG-01 证据读取；不修 `regime.decide`。
