# 0.4.14 冻结版本说明（对外 PoC 冻结版）

> 本文件说明 0.4.14 的冻结范围、与 0.4.13 / 0.4.12 / 0.4.11 / 0.4.10 的关系、摘要不变量与历史版本保留清单。
> 对外交付以 **0.4.14** 为准；0.4.10 为历史验收基线；0.4.11、0.4.12 曾冻结但**未对外**；
> 0.4.13 曾对外（第十五轮），因发行 README 残留绝对化表述、由 **0.4.14 重出重签**取代。

## 1. 冻结结论

- **0.4.14 是当前对外 PoC 冻结版**。
- 0.4.14 只修**文档表述**，不动规则语义与判定逻辑：
  - `release/README-验收.md` §6 原写“`SHA256SUMS` 覆盖除自身与 `SHA256SUMS.sig` 之外的
    发行文件”（绝对化，与实物 5 行不符）。0.4.13 只改了 §1、漏了 §6，且该文件在签名
    保护范围内，因此必须**重出并重签**。
  - 模板 `scripts/build_release.py` 的 §6 同步改写，使这句话不可能再被生成出来；
    全文扫描后不再有“全部发行文件 / 所有发行文件”这类绝对化表述。
  - 新增**对外演示指引**（发行 README 顶部 + 仓库 README 顶部）：演示“删输入被拦截”
    必须用带外部锚点的 v3 包；默认 v2 包删输入后仍只是 `RESULT PARTIAL`（exit 2）。
  - `未随交付清单.md` 与 README 的口径改为准确表述，并登记 `reports/*.md` 中对
    `dist/` 的出处引用（不影响验算）。
- **0.4.13** 修复了第二轮盲验的阻断缺陷（默认 v2 包被判 `INPUTS FAIL` exit 1），该修复由
  0.4.14 继续继承；0.4.13 发行物与第十五轮交接**保留只读**。
- **0.4.12 未对外**，原因一句话：默认流程产物被自家验算器判 `RESULT FAIL`（exit 1），
  属阻断交付的功能缺陷；且 `RELEASE.json` / `release/README-验收.md` 写“覆盖全部发行文件”，
  与实物 5 行不符。0.4.12 发行物与第十四轮交接**保留只读**。
- **0.4.11 曾冻结但未对外**：其发行 README 保留“v6 新包配 0.4.8 wheel”的 0.4.8 时点旧句，
  接收方照做会 `PRODUCER FAIL`。
- 0.4.10 为历史验收基线。
  `dist/wca-replay-0.4.10/`、`0.4.11/`、`0.4.12/`、`0.4.13/` 与第十二至十五轮交接**一律不改动**。

## 3.1 0.4.13 修复继续有效（已实测）

- schema v3 缺 `inputs_digest` → `INPUTS FAIL`（exit 1）；schema v2 缺该字段 → `NOT CHECKED`，
  最多 `RESULT PARTIAL`（exit 2）。默认无钥 `wca all` 产物不再被判 FAIL。

## 3.2 0.4.11→0.4.12 的变更性质（可独立复核）

0.4.12 相对 0.4.11 **仅文档与生成脚本变更，无规则语义变更**。该结论不再依赖仓库：
`README.md` 给出 wheel diff 命令，对两版 wheel 逐文件比 SHA-256，实测只有
`policies/RULE-PACK.md`、`src/__init__.py`（版本号）、`src/_release_info.py`
（版本号/BUILD_COMMIT）变化，`src/` 其余模块逐字节相同。外部人只拿两版 wheel 即可自证。

## 5. 版本与 wheel 配对

- **0.4.14 的举证包必须配 0.4.14 wheel 验算**（包内 `producer.version` 与 wheel 版本不一致会
  `PRODUCER FAIL`，属配对问题，不是篡改）。
- **0.4.10 / 0.4.11 / 0.4.12 / 0.4.13 wheel 必须保留**，用于验算对应历史包；交接内清单位于
  `release/old-wheels/`，见 `OLD-WHEELS.md`。
- 0.4.4–0.4.8 旧 wheel 不做 `comparability_scope` 判定；0.4.9 起才有。
