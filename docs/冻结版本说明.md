# 0.4.15 冻结版本说明（对外 PoC 冻结版）

> 本文件说明 0.4.15 的冻结范围、与 0.4.14 及更早版本的关系、摘要不变量与历史版本保留清单。
> 对外交付以 **0.4.15** 为准；0.4.14 曾被第四轮盲验查出 14 条“文档与实物不符”，
> 由 **0.4.15 重出重签**取代。0.4.10 为历史验收基线；0.4.11、0.4.12 曾冻结但**未对外**；
> 0.4.13 曾对外（第十五轮）。

## 1. 冻结结论

- **0.4.15 是当前对外 PoC 冻结版**。
- 0.4.15 只改**文档与文档生成机制**，不动规则语义与判定逻辑。第四轮盲验已证明“逐句修补”
  不收敛（同一事实手写在多处，抄写者知道答案就不会去核），因此本轮改机制：

  | 机制 | 落点 | 解决的问题 |
  | --- | --- | --- |
  | 机制 1：事实由程序生成 | `scripts/docfacts.py` + `scripts/build_release.py` + `scripts/build_handoff.py`，生成区用 `<!-- GENERATED:START … -->` 标记 | 文件数、字节、逐文件 SHA-256、八包表、`SHA256SUMS` 覆盖清单、旧物与旧锚点、章节号 |
  | 机制 2：示例命令必须真跑 | `tests/test_doc_commands.py` | 命令缺必需门禁参数、退出码/`RESULT` 标签与文档不符、命令无期望 |
  | 机制 3：“什么变了”由 diff 生成 | `scripts/diff_packages.py` | `artifacts_digest` 变化原因被概括成“仅因版本号” |

- **0.4.14** 修复了第三轮盲验的文档表述问题（发行 README §6 绝对化表述、演示指引缺失），
  但第四轮盲验又查出 14 条（A1–A3 / B1–B4 / C1–C6 / D1）与 1 条 PG 计数口径不一致。
  0.4.14 发行物与第十六轮交接**保留只读**。
- **0.4.13** 修复了第二轮盲验的阻断缺陷（默认 v2 包被判 `INPUTS FAIL` exit 1），该修复由
  0.4.14、0.4.15 继续继承；0.4.13 发行物与第十五轮交接**保留只读**。
- **0.4.12 未对外**：默认流程产物被自家验算器判 `RESULT FAIL`（exit 1），属阻断缺陷；
  且发行 README 写“覆盖全部发行文件”，与实物 5 行不符。保留只读。
- **0.4.11 曾冻结但未对外**：发行 README 残留“v6 新包配 0.4.8 wheel”的旧句，照做会
  `PRODUCER FAIL`。
- 0.4.10 为历史验收基线。`dist/wca-replay-0.4.10/`、`0.4.11/`、`0.4.12/`、`0.4.13/`、
  `0.4.14/` 与第十二至十六轮交接**一律不改动**。

## 2. 摘要不变量（0.4.15 必须与 0.4.14 / 0.4.13 / 0.4.12 / 0.4.11 / 0.4.10 逐包相同）

八包 `conclusion_digest` 逐包相同：

| 包 | conclusion_digest |
| --- | --- |
| 四主包（engine-only / confirmed / cross-db / reverse-order） | `5dc46558…` |
| default-flow | `0ae2cfe9…` |
| dup-subdir 两包 | `924c5e01…` |
| clean-wheel-default-flow | `a4e31ef3…` |

其余不变量：

- 四主包 `evidence_digest` = `ed3b3f1b…`
- 四主包 `inputs_digest` = `aad527d1…`
- 四主包 `input_fingerprint` = `8b3b54a0…`

**`artifacts_digest` 会变，但原因必须逐包逐文件说明**，不得概括为“仅因版本号”。
本轮实测（`scripts/diff_packages.py` 逐字段比对 0.4.14 → 0.4.15）：

- `policies/CONFIDENCE.md`：只变版本串（版本号文本）；
- `manifest.json`、`audit_chain.jsonl`：版本串 + 真实时间戳 + 派生哈希（签名、摘要、链头）；
- confirmed 包 `conclusions_final.csv`、`responsibility.json`：**时间戳真的变了**，
  `conclusions_sha256` 随之变；
- `RULE-PACK.md`：在八个包内**逐字节未变**（差异表中不出现该成员）。

## 3.1 0.4.13 修复继续有效（已实测）

- schema v3 缺 `inputs_digest` → `INPUTS FAIL`（exit 1）；schema v2 缺该字段 → `NOT CHECKED`，
  最多 `RESULT PARTIAL`（exit 2）。默认无钥 `wca all` 产物不再被判 FAIL。

## 3.2 0.4.11→0.4.12 的变更性质（可独立复核）

0.4.12 相对 0.4.11 **仅文档与生成脚本变更，无规则语义变更**。该结论不再依赖仓库：
`README.md` 给出 wheel diff 命令，对两版 wheel 逐文件比 SHA-256，实测只有
`policies/RULE-PACK.md`、`src/__init__.py`（版本号）、`src/_release_info.py`
（版本号/BUILD_COMMIT）变化，`src/` 其余模块逐字节相同。外部人只拿两版 wheel 即可自证。

## 5. 版本与 wheel 配对

- **0.4.15 的举证包必须配 0.4.15 wheel 验算**（包内 `producer.version` 与 wheel 版本不一致会
  `PRODUCER FAIL`，属配对问题，不是篡改）。
- **0.4.10 / 0.4.11 / 0.4.12 / 0.4.13 / 0.4.14 wheel 必须保留**，用于验算对应历史包；
  交接内清单位于 `release/old-wheels/`，见 `OLD-WHEELS.md`。
- 0.4.4–0.4.8 旧 wheel 不做 `comparability_scope` 判定；0.4.9 起才有。
