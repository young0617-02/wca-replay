# 冻结版本说明（0.4.18 → 0.4.19，对外 PoC 冻结版）

> 本文件说明 0.4.19 的冻结范围、与 0.4.17 / 0.4.18 及更早版本的关系、摘要不变量与历史版本保留清单。
> **本轮对外交付为 0.4.19**（只改包内金额口径文案；规则语义、判定逻辑、摘要算法、导出列集均未动）；
> 其包级四联值与 0.4.18 逐包相同。0.4.18 为上一轮冻结基线（`approved_conclusions` 新增、
> `signed` 改名 `delivery_registered`、导出默认裁剪姓名/工号），0.4.17 只修锚点与扫描器。
> 0.4.14 曾被第四轮盲验查出 14 条“文档与实物不符”，由 **0.4.15 重出重签**取代。
> 0.4.10 为历史验收基线；0.4.11、0.4.12 曾冻结但**未对外**；0.4.13 曾对外（第十五轮）。

## 1. 冻结结论

- **0.4.19 是当前对外 PoC 冻结版**；本页其余内容描述历史版本的冻结口径，仍然有效。
- 0.4.19 只改包内可见的金额口径文案（`README.txt`、`manifest.disclaimer`、
  `not_covered.json` / `未覆盖清单.md`、`responsibility.json.principle`），详见
  `reports/0.4.19-包内文案修订.md`；**不动规则语义、判定逻辑、四联摘要与导出列集**。
- 0.4.18 只改责任块字段名与导出列集（详见
  `reports/0.4.18-已确认结论拆分与导出裁剪.md`），**不动规则语义、判定逻辑与摘要算法**；
  旧包由 `wca-verify` / `wca replay` 双读兼容。
- 0.4.17 只改**锚点生成/命名、扫描器与文档**，不动规则语义与判定逻辑。第六轮盲验的
  2 条阻断都在锚点上：`anchor-0.4.14.json` 文件名叫 0.4.14、内容实为 0.4.15，且真正的
  0.4.15 组合锚点缺失；历史锚点的 `file` 字段多数指向不存在的裸文件名。处置见
  `reports/0.4.17-锚点纠正与扫描器扩展.md`。
- 0.4.16 只改文档生成机制与残留页（第十六条处置见 `reports/0.4.16-护栏加固与残留页.md`）。
- 0.4.15 建立的三条机制继续有效：

  | 机制 | 落点 | 解决的问题 |
  | --- | --- | --- |
  | 机制 1：事实由程序生成 | `scripts/docfacts.py` + `scripts/build_release.py` + `scripts/build_handoff.py`，生成区用 `<!-- GENERATED:START … -->` 标记 | 文件数、字节、逐文件 SHA-256、八包表、`SHA256SUMS` 覆盖清单、旧物与旧锚点、章节号 |
  | 机制 2：示例命令必须真跑 | `tests/test_doc_commands.py` | 命令缺必需门禁参数、退出码/`RESULT` 标签与文档不符、命令无期望 |
  | 机制 3：“什么变了”由 diff 生成 | `scripts/diff_packages.py` | `artifacts_digest` 变化原因被概括成“仅因版本号” |

- **0.4.14** 修复了第三轮盲验的文档表述问题（发行 README §6 绝对化表述、演示指引缺失），
  但第四轮盲验又查出 14 条（A1–A3 / B1–B4 / C1–C6 / D1）与 1 条 PG 计数口径不一致。
  0.4.14 发行物与第十六轮交接**保留只读**。
- **0.4.13** 修复了第二轮盲验的阻断缺陷（默认 v2 包被判 `INPUTS FAIL` exit 1），该修复由
  0.4.14、0.4.15 继续继承；0.4.13 发行物与第十五轮交接**保留只读**。
- **0.4.12 未对外**：默认流程产物被自家验算器判 `RESULT FAIL`（exit 1），属阻断缺陷；
  且发行 README 写“覆盖全部发行文件”，与实物 5 行不符。保留只读。
- **0.4.11 曾冻结但未对外**：发行 README 残留“v6 新包配 0.4.8 wheel”的旧句，照做会
  `PRODUCER FAIL`。
- 0.4.10 为历史验收基线。`dist/wca-replay-0.4.10/`、`0.4.11/`、`0.4.12/`、`0.4.13/`、

## 3.1 0.4.13 修复继续有效（已实测）

- schema v3 缺 `inputs_digest` → `INPUTS FAIL`（exit 1）；schema v2 缺该字段 → `NOT CHECKED`，
  最多 `RESULT PARTIAL`（exit 2）。默认无钥 `wca all` 产物不再被判 FAIL。

## 3.2 0.4.11→0.4.12 的变更性质（可独立复核）

0.4.12 相对 0.4.11 **仅文档与生成脚本变更，无规则语义变更**。该结论不再依赖仓库：
`README.md` 给出 wheel diff 命令，对两版 wheel 逐文件比 SHA-256，实测只有
`policies/RULE-PACK.md`、`src/__init__.py`（版本号）、`src/_release_info.py`
（版本号/BUILD_COMMIT）变化，`src/` 其余模块逐字节相同。外部人只拿两版 wheel 即可自证。

## 8. 锚点生成规则（0.4.17 起）

- 文件名由内容 `version` 派生：`anchor-<版本>-<role>.json`（单包）/ `anchor-<版本>.json`（组合）；
- 构建断言：**文件名版本 == 内容版本 == 目标包 `producer.version`**，任一不一致直接失败；
- `file` 只允许两种值：以**该 JSON 自身位置**为基准可解析的相对路径，或显式“仅记录、不可解析”；
  不再复制沿用源文件名，也不再写根目录不存在的裸文件名；
- 历史锚点来源、0.4.12 缺包与获取方式，见交接目录 `OLD-ANCHORS.md`（由扫描器遍历 `anchor*.json` 生成）。
