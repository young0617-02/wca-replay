## 1. MVP 是什么

**一句话**：把"一条不会赔钱的判断链"做成**能演示、能复跑、能被第三方离线复核**的最小闭环——确定性引擎算工时、引擎**不产出金额**、AI 只解释带出处的规则、金额与结论由具名人工确认，评审者在**没有云凭证**的干净环境里一条命令复现。

### 1.1 最小闭环（一条链跑通即成立）

```
上传 CSV → 质量门禁拦脏 → 城市档（广州/深圳/佛山）+ 规则版本
        → 标准工时 6 判据（J1~J6，引擎无金额输出）
        → 异常三级（可申辩/需复核/明显违规）+ 规则 ID + 条文号 + 原始行号
        → HR 负责人界面复核、具名登记结论、录入金额、签发
        → 导出举证包（hash 链 + 三元组 + 责任标注 + 未覆盖清单）
        → 外部接收方仅凭包内材料重放，结论逐条一致
并行第二条链：提问 → 会话身份 → ACL 谓词下推检索 → 数值取规则引擎
        → 出处 + 证据覆盖率 → 金额类只解释不给数 → 低置信转人工待答队列
        → 界面明示"内容由 AI 生成"
第三条链（证明前两条可信）：判据冻结 → ≥60 条三档评测集 → 判分器
        → 变异测试 → 三态口径声明 → 无凭证复跑
```

**MVP 不追求**：界面美观、覆盖全部工时制、真实企业数据、成本优势论断、模型能力本身。

## 2. 范围切分

### 2.1 包含：标准工时 6 类判据（8 小时制，广州 / 深圳 / **佛山** 三档）

城市档次于 2026-10-08 定为 **3 市**（DEC-02：第三个城市 = 佛山）。三市共用同一组 6 类判据，但**条文集合按市分档存**，不得一套规则强盖三城（需求 §7.3-3）。

| 判据 | 认定内容 | 基线承载规则 | 本 MVP 的处理 |
|---|---|---|---|
| J1 工作日超每日 8 小时的延长工时 | 超出分钟数 + 150% 档位 | `OT-D01` | 复用，**删除金额测算字段**（GAP-01） |
| J2 周超 40 小时 | 周分钟数与 44h/40h 口径差异 | `WK-W01` `WK-W02` | 复用；两口径差异继续"标注不硬判"，条文关系在闸门文档里写清 |
| J3 每月延长工时累计上限 | 月累计分钟 vs 上限 | `CAP-M01` `CAP-M02` | 复用；统计口径（休息日是否计入）作为配置项并披露 |
| J4 工作日延长 → 倍数档位 | 150% | `OT-D01` | 复用（只出档位与分钟数） |
| J5 休息日出勤 → 倍数档位与补休口径 | 200% / 可安排补休 | `OT-D02` | 复用 |
| J6 法定节假日出勤 → 档位与"不得以补休替代" | 300% | `OT-D03` | 复用；年度日历未核实的年份继续落 `SCOPE-01` 未覆盖 |

条文号一律视为**待核锚点**，须逐条比对现行官方文本后才可写入条文清单（需求 §0「条文」规则 + 附录 B-9）。

### 2.2 包含：其他四项

1. 四类 CSV 导入 + 质量门禁 + 行级来源三元组（`复用`）。
2. 举证包：hash 链 + 三元组 + 责任标注 + 未覆盖清单（`复用`，需补责任标注与未覆盖清单两节）。
3. 带 ACL 下推的制度问答 + 出处 + 覆盖率 + 置信门禁 + 金额只解释 + 人工待答队列（`复用`，需改外发内容，GAP-07）。
4. **Web 界面 3 视图 + 最小登录**（`新建`，**2.0 人日**——原 2.5，让出 0.5 给三市条文档，`TECH-04` / 技术方案 §6.2）。
5. ≥60 条三档评测集 + 判分器 + 变异测试 + 三态口径声明 + 30 分钟演示脚本（`改动`：需按新判据与**三市**重算，GAP-10）。

## 7. 超支、砍范围与停手规则

1. **闸门失败即停手**：S1 结束时若"公开资料凑不齐字段语义表"或"J1~J6 条文依据找不齐"，按需求 §7.3-1 停止本项目并切备选方向；**禁止**"先按假设做起来，之后再补口径"。
2. **超支砍序**（需求 §6.3，M1 红线永不砍）：Could（OW-05/RV-05）→ Should（RV-04/AD-05/EX-03/EV-07/UI-04）→ 界面内部（UI-04 → UI-02 → UI-01）→ 才谈范围；砍到 M1 红线就要停手。
3. **界面余量只剩 0.5**：S5 按 **2.0 人日**排（需求 §7.2 的 2.5 是上限，不是必须花满的额度；0.5 已由 DEC-02 让给三市条文档）。超 2.5 仍然只能砍界面，**不得**追加总人日。
4. **本期已砍项**（因佛山入范围，逐条留痕，不得再当作可选项）：
   - **UI-04 / V-11 的 `export_parity` 双通道逐字节 diff 验收** → 由单一入口结构性替代（省 0.5）
   - **缓冲 0.5 → 0.0**（省 0.5）
   - **EV-07 演示脚本独立彩排** → S7 只写脚本，盲跑计时标"未做/未测"（省 0.1）
   合计 1.1 = 三市多出的 1.1 人日（P0 +0.4、P2 +0.7），与需求 D-06 指定的来源一致。
   **不砍清单**：US-UI-02 复核台界面（需求 §5.1 断点表已说明为何 Must）、US-EX-03 未覆盖清单、M1 红线全部故事。
5. **三城分歧不许强行合一**：同一判据三城口径不一致时分档实现或标未覆盖（需求 §7.3-3，广深/广佛/深佛逐对比对）。
6. **界面与脚本结果不一致**：以脚本为准，界面当天退回（双实现的唯一裁定规则）。
