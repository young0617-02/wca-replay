## 1. 项目背景与目标

### 1.1 核心业务问题

中小企业在劳动争议（尤其加班费争议）中的真实风险，不是"考勤不好管"，而是**拿不出一条可举证、可复核、可追溯的工时链**：

- 原始打卡/请假数据来路不清（哪个文件、哪一行、有没有改过）；
- 超时加班、休息日与法定节假日倍数等口径不统一，且随城市与条文层级不同；
- AI/系统给出的结论**没有出处、没有责任人、金额还可能算错**，在仲裁中不构成可用证据。

在位 HR SaaS 把这一格当附属功能，恰好是单人能做深、且**标准答案公开可查**的窄缝。

### 1.2 一句话定位

**不是"做了一个 HR 系统"，是"做了一个不会赔钱的判断链"**：工时判定一律由确定性规则引擎计算，**引擎不输出应付金额**，AI 只解释规则并给出带出处的依据，金额与最终结论由具名人工确认，全程留痕可复核。

### 1.3 业务闭环要达成的终态

一次完整运行必须同时闭合三条链（详见 §5）：

1. **场景内业务闭环**：HR 专员在**界面**导入打卡/请假数据 → 质量门禁 → 确定性合规校验（标准工时 6 类判据）→ 异常分级 → HR 负责人在**复核台**人工确认并具名 → 举证包导出 → 外部接收方**仅凭包内信息**即可复核每条结论。
2. **问答与责任链**：任意角色经**问答界面**提问 → 权限谓词在检索层下推 → 带可点开出处与证据覆盖率的解释 → 金额类事项**只解释规则、不给数额** → 低置信/高风险进入人工待答队列 → 全链路留痕，且界面明示内容由 AI 生成。
3. **证据链**：判据冻结 → ≥60 条三档评测集（每条有可复核条文依据）→ 判分器 → 变异测试证明套件有鉴别力 → 评测报告与三态口径声明 → 评审者在干净环境、**无云 API 凭证的情况下**复跑确定性部分。

## 2. 用户角色定义

| 角色码 | 角色 | 现实对应 | 使用通道 | 权限域 | 在闭环中的职责 |
|---|---|---|---|---|---|
| OW | **项目负责人**（唯一实现者） | 开发者本人，兼合规口径责任人 | 配置文件 + 脚本 | 全部；唯一可冻结判据、可宣告 No-Go 的角色 | 闸门取证（公开资料字段口径 + 三地条文）、合成数据规则、判据冻结、停止/切换决策 |
| OP | **HR 专员**（数据操作员） | 中小企业人事/行政 | **Web 界面**（导入/异常）+ 脚本 | 全体员工打卡/请假/出差数据；**不可见薪酬与金额类受限条目** | 导入数据、发起校验、处置异常报表、导出举证包 |
| RV | **HR 负责人**（复核与签发人） | HR 主管/人事经理 | **Web 界面**（复核台） | 员工数据 + 受限条目 + 复核结论登记权 + 签发权 | 人工复核、金额录入与最终确认（具名）、举证包签发 |
| EM | **普通员工** | 被核算工时的劳动者 | **Web 界面**（问答） | **仅本人**工时结论 + 公开制度条目；他人数据不可见即不可召回 | 自查本人工时、查制度依据；接受"金额需人工确认"的引导 |
| AD | **系统管理员** | 由 OW 兼任 | 配置文件 + 脚本 | 知识库条目、用户与可见域、规则版本、模型后端与密钥 | 维护 ACL 数据来源与规则版本，保证历史举证包可复现 |
| EX | **外部接收方**（仲裁员/第三方审计/企业法务） | 争议中的证据审阅者 | **离线接收举证包**，不登录 | 只读举证包及其引用的原始行级数据 | 独立复核结论；判断哪些环节由 AI 参与、由谁确认 |
| EV | **复跑评审者** | 面试官 / 开源仓库读者 | 读仓库、跑命令 | 代码、测试、评测报告、口径声明、演示脚本 | 复跑测试与评测，检验每个数字的溯源 |

> 说明一：EX 与 EV 是本项目**真正的价值出口**。前者代表"举证"这一业务价值落点，后者代表"可复跑证据"这一作品集目标落点。缺任一方，闭环都不成立。
> 说明二：现实约束——本项目为单人求职作品集，**无真实客户、无真实员工数据、无 HR 访谈**（本版决定 1）。表中角色是**场景内角色**，其权限模型与界面必须真实实现，以便 EX/EV 按同一套语义复核。
> 说明三：界面不新增人员角色，只改变 OP/RV/EM 的使用通道；**权限判定一律在服务端**（NFR-16）。

## 5. 业务闭环说明

### 5.1 闭环① 工时举证链（数据 → 外部采信）

```
US-OW-01/02（公开资料字段口径 + 三地条文清单，闸门）
   └→ US-OW-03（合成数据，两市，可复现）
        └→ US-UI-01 ←→ US-OP-01（导入：行级来源三元组）
             └→ US-OP-02（质量门禁）──脏数据 → 界面异常报表 → 回退给 OP 修正（不得带脏进入校验）
                  └→ US-OP-03（选定 城市 + 规则版本）
                       └→ US-AD-03（规则版本与未支持项）
                            └→ 确定性校验：标准工时 6 类判据（数值不经 LLM，且**不产出金额**）
                                 └→ US-OP-04（异常三级分类 + 规则 ID + 条文号）
                                      └→ US-UI-02 → US-RV-01（人工复核结论，具名）
                                           └→ US-RV-04（签发）
                                                └→ US-OP-05 / US-UI-04（导出举证包）
                                                     ├→ US-AD-04（hash 链完整性）
                                                     └→ US-EX-01/02（外部离线复核一致、责任可分）
```

**闭环成立判据**：US-EX-01 的"仅凭包内信息重跑一致"通过。任一环缺失即断链——

| 断点 | 后果 |
|---|---|
| 无 US-OP-01 行级溯源 | 外部无法验证输入真实性，举证包降级为自说自话 |
| 无 US-RV-01 人工结论 | 系统输出变成机器单方结论，重现"AI 取证不被采信"的失败模式 |
| 无 US-AD-03 规则版本与未支持项 | 换口径重跑结论不同，历史举证包不可复现；缺项被读成造假 |
| 无 US-OP-02 质量门禁 | 缺卡被当作加班缺失，结论方向性错误 |
| 复核只存在于脚本、界面走不通 | 实际操作者不会去跑脚本，闭环在真实使用中断掉（故 UI-02 为 Must） |

### 5.2 闭环② 问答与责任链（提问 → 有依据、有责任人）

```
提问（EM / OP / RV，经 US-UI-03 问答界面）
   └→ US-UI-05 最小登录 → US-AD-02 用户-角色-可见域
        └→ US-EM-04 / US-RV-02：ACL 谓词下推到检索层（不得先召回再过滤）
             └→ US-AD-01 知识库条目（出处/生效日期/地域层级/版本）
                  └→ US-EM-01/02：数值取规则引擎 + 每条答案带可点开出处与证据覆盖率
                       ├→ 高置信 + 非金额类 → 给出规则解释
                       ├→ 金额/加班费/赔偿类 → US-EM-03：只解释口径、页面不出现任何金额数字
                       ├→ 低置信 / 证据不足 → US-RV-03 人工待答队列
                       └→ 云后端不可达 → US-AD-05 明确降级提示，不编造
                            └→ 全程留痕 + NFR-17 AI 标识 → 进入 US-EX-02 责任标注
```

**闭环成立判据**：US-EM-03（错承诺 = 0）与 US-EM-04（越权召回 = 0）同时通过。任一不通过，问答层就是**风险源**而不是价值源，必须关掉该接口/该视图而非带病演示。

### 5.3 闭环③ 证据链（实现 → 可被第三方验证）

```
US-OW-02 条文依据 ─┐
                   ├→ US-EV-02 ≥60 条三档评测集（标准答案可指条文）
US-OW-04 判据冻结 ─┘        └→ US-EV-03 判分器与七项指标
                                  └→ US-EV-04 变异测试（注入 ≥5 → 捕获 ≥5/5 → 还原哈希一致）
                                       └→ US-EV-05 三态口径声明（含"未经 HR 访谈"声明）
                                            └→ US-EV-01（无凭证可复跑）+ US-EV-06/07
                                                 └→ EX/EV 采信
```

**为什么必须有闭环③**：本项目的实际价值出口是"每个数字都能溯源"。没有变异测试，评测分数无法证明判分器有效；没有三态口径声明，设计值会被读成实测值；**没有无凭证可跑路径，改用云 API 后评审者根本无法复跑，A6 直接失效**（本版新增的关键依赖）。

## 6. 范围边界

### 6.1 包含（In scope）

**A. 合规校验判据（标准工时制，8 小时制，广州/深圳）** — 全部由确定性规则实现，本期只做这 6 类：

| # | 判据 | 依据锚点（**须核对现行官方文本后才写入条文清单**） |
|---|---|---|
| J1 | 工作日超出每日 8 小时的延长工时认定 | 标准工时每日 8 小时口径（国务院《关于职工工作时间的规定》第 3 条；《劳动法》第 36 条为每周 44 小时上限口径，二者关系须核对并写清） |
| J2 | 周超出 40 小时的工时认定 | 同上（每周 40 小时口径） |
| J3 | 每月延长工时累计上限认定 | 《劳动法》第 41 条（延长工时每日/每月上限口径） |
| J4 | 工作日延长 → 倍数档位认定 | 《劳动法》第 44 条第一项 |
| J5 | 休息日出勤 → 倍数档位认定与"可安排补休"口径 | 《劳动法》第 44 条第二项 |
| J6 | 法定节假日出勤 → 倍数档位认定与"不得以补休替代"口径 | 《劳动法》第 44 条第三项 + 当年度国务院办公厅节假日安排通知（按年度入库，带出处） |

> 引擎输出：小时数 + 适用倍数档位 + 触发规则 ID + 条文号。**引擎不输出应付金额**；金额由 RV 在复核台录入并具名确认（§1.2）。

**B. 其他包含项**

1. 四类 CSV（打卡/请假/出差/补卡）导入与数据质量门禁，行级来源可追溯。
2. 举证包导出：审计日志 hash 链 + 三元组 + 责任标注 + 未覆盖清单。
3. 带 ACL 下推的知识库与制度/法条问答，含出处、证据覆盖率、置信度门禁、金额类事项只解释不确认、人工待答队列。
4. **只读 + 必要写接口的 Web 界面**：导入与异常、复核台、问答 3 视图 + 最小登录；HTTP 层在原有 2 个只读接口（问答、导出）基础上增加界面所需的会话与结论登记接口。
5. ≥60 条三档评测集、判分器、单测、变异测试、三态口径声明、30 分钟演示脚本。

### 6.2 不包含（Won't have，明确拒绝，不得因"顺手"加入）

| 不做什么 | 为什么不做 |
|---|---|
| **综合计算工时 / 不定时工时的周期超额校验**（本版决定 2 退出范围） | 工时制锁定 8 小时标准工时；周期汇总与审批口径会引入无限判据分支（R2）。**必须写入未覆盖清单**（US-EX-03），面试时的标准答法见 §7.4-D-02 |
| 多租户 SaaS、组织同步（钉钉/飞书/企微）、账号商业化 | 需要主体与合规责任，属已商品化能力 |
| 审批流引擎、线上申辩流 | 闭环只到"异常标记 + 人工复核结论 + 签发"；申辩是流程系统的事 |
| 排班优化求解（OR-Tools/CSP） | 3–6 人月独立难点，与举证目标无关 |
| **加班费金额自动计算、薪酬/社保/发薪** | 金额依赖薪酬基数与个体工资数据，既是 PIPL 敏感项又是跨城市永久性维护负债；本项目命题是"不赔钱的判断链"，金额交给人 |
| 完整考勤计算引擎（全量工时口径、复杂跨天夜班） | 只做**校验**不做全量计算；复杂项 3 天未收敛即标注"未支持" |
| 前端框架/构建流水线/图表看板/主题美化/响应式适配 | 界面预算 2.5 人日只够"能走完闭环的操作路径"，不够"好看的界面" |
| 第三方登录、SSO、密码找回、注册流 | 最小登录够用（US-UI-05）；其余是账号系统的无底洞 |
| 考勤硬件对接、私有化部署、等保备案 | 非 19.5 人日事项，且需主体 |
| 真实客户、真实员工数据、任何"上线/在用/覆盖 XX 人"表述 | 无主体、无数据来源；A10 一票否决 |
| 训练/微调模型 | 目标不是模型能力，是判断链工程 |

### 6.3 边界裁定规则

- 新需求默认**拒**，除非能指出它让 §5 某条闭环的判据更容易通过；否则进 `【填：待议需求池】`，本期不实现。
- 时间冲突时按 §7 顺序砍：先砍 Could，再砍 Should，再砍界面（UI 内部顺序 UI-04 → UI-02 → UI-01），**M1 红线永不砍**；**M1 红线 = 不砍范围就停手**。
- 未做访谈后的表述纪律：所有"业务价值"论断只能写成"公开法条口径 + 规则可复核"，**禁止**声称反映某类企业实际管理需求或"与 HR 确认过"。
- 任何"看起来更真实"的做法（拿真实员工数据、宣称有客户、把设计阈值说成实测）一律禁止——PIPL 与 A10/A11 双重红线。

5. **界面与脚本结果不一致** → 以脚本为准，界面当天退回（这是双实现风险的唯一裁定规则）。
