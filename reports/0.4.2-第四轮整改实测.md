## 6. 仍未闭合 / 不能声称

- **旧 0.4.1 签名包与 0.4.2 wheel**：`producer.version`/`commit` 不一致会先触发
  `PRODUCER FAIL`（既有失败关闭策略）；`EVIDENCE DIGEST NOT CHECKED` 分档只适用于无 `producer`
  的历史包。不能把 0.4.1 包当成“0.4.2 同版本可复算”。
- **`evidence_digest` 不在四段锚点内**：它在 manifest 内并受 `manifest_checksum` 与签名覆盖，
  但包外锚点仍是 schema/规则版本/输入指纹/结论摘要四段。只换 evidence 并重签、同时替换
  manifest 与包 SHA 仍可能发生，必须靠外部 pin/锚点/包 SHA 与 `artifacts_digest`。
- **跨 run `inputs_digest` 的边界**：实测是同一临时 SQLite 库、同一批文件；`inputs/manifest.json`
  的 entries 仍含数据库内 `file_id`，换新库重新导入后 `file_id` 可能不同，未证明跨库逐字符相同。
  本次只证明“同库同批输入跨 run 稳定”。
- **24 条中 17 条 REVIEW + 1 条 DEFENSIBLE 不是已定性违规**：它们只是证据定位上无法逐行，
  不能当成 7 条 `VIOLATION` 的同类法律结论。
- **法律实体性未验证**：13 项存疑、城市档位、台账真实性仍需外部律师/劳动监察判断；
  `policies/` 是对外精简版，不是全文法条库。
- **无可复现构建/第三方时间戳/透明度日志**；`SHA256SUMS.sig` 只签 `SHA256SUMS`，不覆盖自身，
  也不证明来源身份。
- 活动库未写、远程未推；本次所有包与临时库均在 `var/`/`handoff/`/`dist/`（均不入库）。
