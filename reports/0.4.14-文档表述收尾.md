# 0.4.14 文档表述收尾（第十六轮）

时间：2026-11-05（Asia/Shanghai）
分支判定：**重出 0.4.14 并重签**。

## 一、分支判定的实测依据

`release/README-验收.md` 第 6 节的绝对化表述位于 `release/SHA256SUMS` 第 1 行
`README-验收.md`——**正是被签名的 5 个顶层文件之一**。因此不能只改副本：

- 0.4.13 的 `SHA256SUMS.sig` 保护着这句话，改文件即破坏签名；
- 只改交接副本会留下模板继续生成错话。

故按用户规则走 0.4.14：改模板 → 升版本 → 重出 → 重签。

## 二、根因

`scripts/build_release.py` 的 README 模板有两处描述 `SHA256SUMS`：§1 已改为“只覆盖构建时
5 个顶层文件”，**§6 仍是旧句**“`SHA256SUMS` 覆盖除自身与 `SHA256SUMS.sig` 之外的发行文件”。
0.4.13 只改 §1、漏改 §6，导致 `release/README-验收.md` 前后自相矛盾。

## 七、默认 `wca all` 实测（0.4.14 wheel，SQLite）

| 场景 | 产物 | 关键行 | exit |
| --- | --- | --- | --- |
| A 无签名钥 | v2 无签名 | `INPUTS DIGEST NOT CHECKED（v2 契约无 inputs_digest；属版本缺失…）`、`SIGNATURE NOT CHECKED`、`RESULT PARTIAL` | 2 |
| B 有签名钥、无外部项 | v3 已签名 | `INPUTS DIGEST OK`、`SIGNATURE OK（package self-check）`、`RESULT PARTIAL` | 2 |
| C B + 外部锚点/包 SHA/两摘要 | v3 已签名 | `SIGNATURE PINNED OK`、`ANCHOR CHECK OK`、`RESULT OK` | 0 |

结论：默认流程产物能被自家验算器正确判定；v2 缺字段是 NOT CHECKED/PARTIAL，不是 FAIL。

### 演示风险实测（支撑 §0 指引）

把 A 场景 v2 包内 `inputs/data/raw/correction.csv` 删掉后验算：

```
ARTIFACTS OK checked=14
ARTIFACTS DIGEST manifest-internal OK / external NOT CHECKED
RESULT PARTIAL
exit 2
```

删输入**不会**变 FAIL。因此对外演示“删输入被拦截”必须用 v3 包 + 外部锚点；否则会给观众
“删了也没事”的错觉。
