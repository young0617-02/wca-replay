## 冻结声明（OW-04，2026-10-08）

**冻结对象**（此后改动一律先升版本、先留 REV）：

- 规则包 `rp-2026.10.gd-pilot-standard.v4` 与 `RULE_CATALOG` 的 16 条判据（含 `SCOPE-02/03/04` 的语义）；
- `config/region_profile.json` 的城市→条文集合映射（广州/佛山→省条例第 20 条，深圳→特区条例第 18 条）；
- 影响结论的判据参数默认值：日/周标准分钟数、每日与每月加班上限、`WCA_OT_CAP_SCOPE`、跨零点切分时刻、夜间时段窗口。

**不在冻结范围内**：展示层与模板、文档措辞、评测集**新增题目**（不改期望口径）、性能路径、举证包的产物清单
（只要结论集合不变，加产物不动版本号——REV-06 就是这一类）。

**冻结效力边界**（别把它读大成"判据已获外部认可"）：冻结只约束**本项目自己的改动纪律**；
条文本身的外部有效性仍以 `docs/字段口径与条文依据.md` 的核对日期（2026-10-08）与其中 13 项未核实清单为准，
字段语义仍是**公开资料，未经 HR 访谈核对**（需求 D-01）。

**已知的后续触发条件**（出现即解冻、升版本、补 REV）：

## REV-07 举证包自含原始输入 + `replay` 重放（US-EX-01 / A8 / S7 追加）

| 项 | 内容 |
|---|---|
| 改了什么 | ① `run` 表新增 `referenced_file_ids` 列（老库走 `ALTER` 迁移），记录本次校验**真正引用到**的输入文件 id；② `export_package` 默认把这些文件打进包内 `inputs/`，附 `inputs/manifest.json`（每个文件的 `rel_path/kind/sha256/bytes/arcname`）与 `manifest.inputs` 区块；③ 包内 `verify.py` 除重算链以外**逐个复算输入哈希**；④ 新增 `src/replay.py` 与 `python -m src.cli replay <包>`：解包 → 在临时库重建事实 → 按包内 scope 钉回口径参数 → 重跑引擎 → 比对三元组；⑤ `ingest.import_csv_file` 增加 `rel_path` 覆盖参数（重放时包内路径与原始路径不同，不复现就比不回指纹） |
| 有没有改判据 | **没有**。结论集合、分级、条文挂载、以及 `input_fingerprint` 的**计算式**一律不变——新列不进 `scope`，因此不参与指纹哈希。实测：加列前后对同一批数据跑校验，`输入指纹 f5021119…`、`结论摘要 95f01ab2…` **逐字符相同**（所以旧包与新包在这里仍可比） |
| 为什么 | 需求 US-EX-01 的判据原文是「只给包内三元组 + 原始 CSV，重放逐条一致」。此前包里没有原始 CSV，`verify.py` 只能证明**包没被改写**，证明不了**结论是这批数据算出来的**；这一条缺口不是靠文字声明能糊过去的，得有一条真能跑的命令 |
| 打包集合为什么是四个并集 | `主数据(org/employee) ∪ 引用集合 ∪ 结论溯源引用 ∪ 未归属质量问题所在文件`。org/employee 从不出现在 `source_refs` 里，漏掉它，接收方重放会得到"0 员工 0 结论"，看起来像引擎不可复现，其实是**包缺件**；`QUAL-02` 那类归属不到人的结论扫的是全库 `ingest_issue`，其文件也可能不在引用集合里却改变了结论摘要。这两类都由变异体 M20 守住 |
| 证据 | `tests/test_replay.py` 7 项：包自含 4 个输入 / 重放三元组逐项一致 / 已解压目录同样可重放 / **把打卡 19:00 改成 22:00 后重放必须报不一致** / 改一条审计事件必须报断裂序号 / `--no-inputs` 的包明确拒绝重放而不是假装通过 / 规则包版本不同直接拒。另 `tools/mutation_test.py` 由 19 增至 **20 个变异体，捕获 20** |
| 已知边界（写清，不外推） | ① 升级前的旧 run 没有引用集合：按"主数据 + 溯源 + 未归属"打包，并在 `manifest.inputs.reason` 里如实写明；② 包内 `scope` 只记录了 5 个口径参数（月上限口径、跨零点切分、日/周标准分钟、基数来源），**其余判据参数沿用代码默认值**，重放进程**不读本机 `.env`**——所以重放的可比前提是"同版本代码 + 同默认口径"；③ 1,000 行档的自含输入约 300 KB（本机实测），预算上限 8 MiB，超了直接报错要求 `--no-inputs`，不静默截断 |
| 顺带发现的口径问题（**未擅自改**） | `raw_file.row_count` 对 CSV 通道存的是**表头列数**（`import_csv_file` 传 `len(header)`），而程序化通道 `import_rows` 传的是行数；两通道语义不一致，且这个值参与 `input_fingerprint` 计算。改正属于"改了会让同批数据的指纹值变化"的改动，需要你先裁定（记在 `docs/待确认清单.md` 第 8 项），我不趁这次顺手改 |
