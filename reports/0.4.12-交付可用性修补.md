# 0.4.12 交付可用性修补报告

> 范围：仅文档与生成脚本。引擎、规则包、摘要算法未改动。
> 标注：**[实测]** 有命令或文件字节为证；**[推断]** 由代码/结构推导，未单独跑对抗用例。

## 1. 结论先行

- 0.4.12 是**当前对外 PoC 冻结版**；0.4.11 **曾冻结但未对外**，原因是其发行 README
  第 69 行保留“v6 新包配 0.4.8 wheel”的 0.4.8 时点旧句，接收方照做会拿 0.4.8 wheel
  验 0.4.11 包并得到 `PRODUCER FAIL`（exit 1）。
- 4 项交付可用性问题全部修在**模板源头或交接生成路径**，不是只改已生成文件：
  1) 版本配对硬编码（`scripts/build_release.py` + `policies/RULE-PACK.md`）；
  2) 交接内 wheel 路径（README + `OLD-WHEELS.md` → `release/old-wheels/`）；
  3) `docs/安全与证据链现状.md` 实际交付 + 链接自检；
  4) README 首页 PoC 边界段（模板与交接 README 均有）。
- 八包 `conclusion_digest`、`evidence_digest`、`inputs_digest`、`input_fingerprint`
  与 0.4.11 **逐字节相同**；只有 `artifacts_digest` 因包内文档版本号与配对表述修正而变。
- 干净 venv（仅 0.4.12 wheel）八包 `verify` + `replay`：**16/16 `RESULT OK`** [实测]。
- 同版本七类篡改仍全部 `FAIL` exit 1；跨版本仍 `INCOMPARABLE` exit 3，未放宽任何真失败 [实测]。

## 2. 四项逐条

### 2.1 必修 1：删除硬编码版本配对

- **问题实物**：`dist/wca-replay-0.4.11/README-验收.md` 第 69 行
  “v5 旧包继续配 0.4.7 wheel，v6 新包配 0.4.8 wheel” [实测：`Select-String` 定位]。
- **根因**：`scripts/build_release.py` 模板内的同一硬编码字符串；只改已生成 README 会在
  下一次构建时复发。
- **修法**：模板改为版本无关表述——“包内 `manifest.producer.version` 必须与所用 wheel
  版本一致；**版本不一致即 `PRODUCER FAIL`（exit 1）**，按 `OLD-WHEELS.md` 换用对应版本
  wheel，不要按‘v5/v6 固定配对某版本’推断”。`policies/RULE-PACK.md` 同步更正。
- **结果**：0.4.12 发行 README 第 75–77 行为新表述 [实测]；`tests/test_round14_docs.py`
  断言模板不含两条旧句、含“不一致即 `PRODUCER FAIL`”。
- **历史残留**：0.4.1–0.4.11 的发行 README 已被 `SHA256SUMS` 与签名覆盖，**不回改**；
  0.4.11 发行物与第十三轮交接保持只读。

### 2.2 必修 2：交接内 wheel 路径可达

- **问题实物**：0.4.11 交接 README 称“0.4.10 wheel 保留在本目录”，实物实际在
  `release/old-wheels/`；`OLD-WHEELS.md` 的目录列写 `dist/wca-replay-0.4.x`，该目录
  不随交接交付 [实测：0.4.11 交接文件]。
- **修法**：README 与 `OLD-WHEELS.md` 统一写相对本交接目录的路径
  `release/old-wheels/<wheel 文件名>`；0.4.10 与 0.4.11 wheel 均复制进该目录。
- **结果**：`scripts/check_handoff_links.py` 解析 README 全部相对链接与
  `OLD-WHEELS.md` 的 wheel 路径，逐条断言存在；生成脚本末尾自动调用，任一缺失即 exit 1
  [实测：生成时自检通过]。

### 2.3 必补 3：引用即交付

- **问题**：多轮 README 引用 `docs/安全与证据链现状.md`，但该文件未在交接目录内。
- **修法**：生成时把该文档复制到交接 `docs/`；README 用可点相对链接
  `[docs/安全与证据链现状.md](docs/安全与证据链现状.md)`。
- **自检**：新增 `scripts/check_handoff_links.py`（解析 markdown 链接与旧 wheel 路径）与
  `tests/test_round14_docs.py::test_handoff_readme_relative_links_resolve`（同一断言）。
- **结果**：交接目录内文档存在、链接可达 [实测]。

### 2.4 必补 4：PoC 边界诚实披露

- **修法**：模板与交接 README 首页均加 PoC 边界段，原文要点：
  “本交付为**验证工具 + 8 个样例包**的 PoC，**不构成合规结论**，**不可作为生产就绪
  依据**；信任根、真实具名确认、法律文本充分性、数据合规四项未闭合，详见
  `docs/安全与证据链现状.md` 第 3 节。”
- **配套**：`docs/安全与证据链现状.md` 第 3 节增加“PoC 四项未闭合速查”表，使“详见第 3 节”
  可逐项落到具体小节 [实测]。
- **测试**：`tests/test_round14_docs.py::test_release_template_has_honest_poc_boundary`
  断言“不构成合规结论”“不可作为生产就绪依据”、四项名称与“第 3 节”均在。

## 4. 干净环境与篡改回归

仓库外干净 venv（`D:\project\wca-clean-0412\venv`，仅装 0.4.12 wheel + 锁定依赖），
八个包 `verify` 与 `replay` 各一遍：**16/16 exit 0 / `RESULT OK`** [实测，
`reports/round14-techcheck.txt`]。同轮专项：

| 场景 | 结果 |
| --- | --- |
| 同版本同 schema、`evidence_digest` 错值 | `RESULT FAIL` exit 1 [实测] |
| 仅传 v6 显式锚点串（v5 包） | `RESULT INCOMPARABLE` exit 3（verify/replay 同）[实测] |
| 用 v6 完整单包锚点文件验 v5 包 | `PACKAGE SHA256 FAIL` → `RESULT FAIL` exit 1（门禁先于可比性）[实测] |
| 缺外部 `artifacts_digest` | `RESULT PARTIAL` exit 2 [实测] |
| 锚点文件缺 `comparability_scope` | `RESULT INCOMPARABLE` exit 3 [实测] |
| `comparability_scope` 与 `anchor` 串矛盾 | `ANCHOR FAIL` exit 1 [实测] |
| 锚点冗余字段与串不一致 | `ANCHOR SELF-CONFLICT` → `RESULT FAIL` exit 1 [实测] |
| 0.4.11 包用 0.4.12 wheel | `PRODUCER FAIL`（配对问题，不是篡改）[实测] |
| 0.4.4–0.4.8 旧 wheel | 无 `comparability_scope` 判定；`RESULT OK` 仅旧口径通过 [实测/推断] |

同版本七类篡改（改 findings、改 quality、删输入、加未声明文件、改 manifest 未重算、
换签名者、替换 verify 脚本）仍全部 `FAIL` 非零，见既有回归用例 [实测]。

## 7. 交付目录补正（不改版本号）

- **背景**：最终验收通过后，审计方指出交接 README 未显式说明“本目录之外的文件不随交付”，
  且 `READ-ME-FIRST.txt` 的“第五、八、十一节/第六节”与实际章节不符（交接 README 只有
  一至十节，验算步骤在 `release/README-验收.md` 第 2–4 节）。
- **改动（仅 `handoff/20261104-第十四轮整改/` 内）**：
  1) README 顶部新增“交付边界（先读）”段，明确 `scripts/`、`tests/`、
     `docs/交付与验收SOP.md` 属仓库内开发参考、不随交付，并给出验算入口
     `release/README-验收.md` 第 2–4 节；
  2) `READ-ME-FIRST.txt` 的节号改为“`release/README-验收.md` 第 2–4 节 / README 第四节”，
     README 内其余“第 3 节”“§4.1”指引逐条核对与目标文件章节一致；
  3) `交付清单.txt` 重算，追加除自身外的逐文件字节与 SHA-256。
- **为什么不开新版本号**：交接 README、`READ-ME-FIRST.txt`、`交付清单.txt` 不在 wheel、
  包签名或 `SHA256SUMS` 覆盖范围内；八包 `conclusion`/`evidence`/`inputs`/`fingerprint`
  与 `artifacts_digest` 全部未变，`dist/wca-replay-0.4.12/` 的 `SHA256SUMS` 与签名保持
  不变。改动不触碰任何包内字节，因此只作交付目录补正，不新开版本。
- **验证**：`scripts/check_handoff_links.py` exit 0；把交接目录整体复制到仓库外，仅用目录
  内 wheel、包、锚点与公钥跑 `wca-verify` 与 `wca replay`，均 `RESULT OK`。
