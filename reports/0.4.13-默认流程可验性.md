# 0.4.13 默认流程可验性实测

日期：2026-11-05（Asia/Shanghai）
环境：`WCA_DB_BACKEND=sqlite`；仓库外干净 venv，仅安装指定版本 wheel + 锁定依赖。

## 1. 缺陷复现（0.4.12 wheel 判 0.4.12 默认产物）

```powershell
# venv: D:\project\wca-clean-0412\venv（仅 0.4.12 wheel）
$env:WCA_DB_BACKEND = 'sqlite'
wca all
wca-verify <wca all 产物.zip>
```

`wca all` 末尾输出：

```text
未签名（v2）；如需签名：--signing-key <私钥文件> 或 WCA_SIGNING_KEY_FILE
```

`wca-verify` 实测（节选）：

```text
MANIFEST SCHEMA v2
MANIFEST CHECKSUM OK
ARTIFACTS OK
FINDINGS DIGEST OK
EVIDENCE DIGEST OK
CHAIN OK
INPUTS COMPLETENESS NOT CHECKED 旧包（schema < 3）
INPUTS DIGEST FAIL
SIGNATURE NOT CHECKED（…）
RESULT FAIL —— INPUTS FAIL 缺少 manifest.inputs_digest
exit 1
```

**结论**：0.4.12 用 FAIL 表达“v2 契约从未有 `inputs_digest`”，与
“旧包缺 `evidence_digest` 记 NOT CHECKED”的既有分档原则冲突；默认流程产物被自家
验算器判不通过，属阻断交付的功能缺陷。

## 2. 修复后：默认 `wca all`（无签名钥）

```powershell
# venv: D:\project\wca-clean-0413\venv（仅 0.4.13 wheel）
$env:WCA_DB_BACKEND = 'sqlite'
Remove-Item Env:WCA_SIGNING_KEY_FILE -ErrorAction SilentlyContinue
wca all
wca-verify <产物.zip>
```

`wca all` 末尾输出（0.4.13 新文案）：

```text
未签名（v2）：wca-verify 最多给 RESULT PARTIAL（exit 2），不能作为完整验收；
如需完整形态：--signing-key <私钥文件> 或 WCA_SIGNING_KEY_FILE（导出 v3）
```

`wca-verify` 实测（节选）：

```text
MANIFEST SCHEMA v2
MANIFEST CHECKSUM OK
ARTIFACTS OK
FINDINGS DIGEST OK
EVIDENCE DIGEST OK
CHAIN OK
INPUTS COMPLETENESS NOT CHECKED 旧包（schema < 3 无完整性对账契约；不是缺失）
INPUTS DIGEST NOT CHECKED（v2 契约无 inputs_digest；属版本缺失，不是缺失/篡改）
SIGNATURE NOT CHECKED（…）
RESULT PARTIAL
exit 2
```

**结论**：默认产物现在能被自家验算器**正确判定**：v2 无签名包 → `RESULT PARTIAL`
（exit 2），不再误判 FAIL；但它**不能作为完整验收**，CLI、README、签名方案三处口径一致。

## 3. 修复后：默认 `wca all`（有签名钥 → 自动 v3）

```powershell
$env:WCA_SIGNING_KEY_FILE = 'var\handoff-keys\ed25519.key'
wca all
wca-verify <产物.zip>            # 不传任何外部锚点
```

实测（节选）：

```text
MANIFEST SCHEMA v3
SIGNATURE OK（package self-check）
SIGNATURE PINNED NOT CHECKED（未提供外部公钥/pin）
ARTIFACTS DIGEST NOT CHECKED / EVIDENCE DIGEST NOT CHECKED（未提供外部值）
RESULT PARTIAL
exit 2
```

补齐外部锚点/包 SHA/工件摘要/证据摘要后（锚点从 manifest 计算的
`schema,rule_pack,fingerprint,conclusion`），同一包实测：

```text
RESULT OK
exit 0
```

**结论**：有钥时默认产物是完整 v3 形态；但要 `RESULT OK` 仍必须由客户提供
**包外**锚点/公钥/包 SHA/摘要——这正是防篡改设计与“默认产物”的边界。

## 6. 直接回答

**默认流程现在产出的包，客户用自家验算器会得到什么结果、exit 几？**

- 不提供签名钥（v2 无签名）：`RESULT PARTIAL`，**exit 2**；
  `INPUTS DIGEST NOT CHECKED`、`SIGNATURE NOT CHECKED`，**不能作为完整验收**。
- 提供签名钥（v3）：内容与签名自洽通过；不提供外部锚点时仍 `RESULT PARTIAL`、**exit 2**；
  提供包外锚点/公钥/包 SHA/摘要后 `RESULT OK`、**exit 0**。
- 无论哪种，**不会**再因“v2 从无 `inputs_digest`”被判 `RESULT FAIL`（exit 1）。
